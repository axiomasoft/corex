# Contributing

## Workflow

1. Branch from `main` with a prefix CI recognises: `feat/`, `fix/`,
   `refactor/`, `chore/` or `hotfix/`.
2. Keep commits small and use [Conventional Commits](https://www.conventionalcommits.org/).
   The body explains what changed and why, for the reviewer.
3. Open a pull request. The `CI gate` check must be green.

## Before you push

```bash
composer lint            # Pint
composer refactor        # Rector
composer analyse         # PHPStan, max level
composer test            # SQLite lane
composer test:pg         # when you touch PostgreSQL behaviour
```

Run the lane that covers your change rather than every suite; CI runs the rest.

## Rules

- **Typing.** `declare(strict_types=1)` everywhere. Use enums and value
  objects instead of magic strings and integers; PHPStan runs at max level with
  strict rules.
- **Public surface.** Mark supported symbols with `#[Api]` or `#[Spi]`, keep
  everything else `#[Internal]`, and refresh the package
  snapshots with `php scripts/php-api.php --strict --write` (`composer php-api`
  verifies them). A contract change
  needs an entry in the package `CHANGELOG.md`; `scripts/contract-guard.sh`
  enforces it.
- **Dependencies.** A package declares everything it uses in its own
  `composer.json`; `composer deps:analyse` checks each package on its own.
- **Schema.** Tables belong to one package. Declare them in the package schema
  sets and in [table ownership](docs/architecture/table-ownership.md).
- **Tests.** A fix comes with a test that fails without it. Do not skip or
  weaken tests or gates; the anti-weakening gate rejects lowered thresholds,
  `continue-on-error`, skipped tests and a shrinking test count.
- **Docs.** English only. Generated references (`docs/architecture/configuration.md`,
  `docs/reference/*`) are regenerated by their scripts, never edited by hand.
- **No local tooling in Git.** Agent and editor configurations, plans and
  scratch files stay untracked (see `.gitignore`).

## Releases

Each package keeps its own `CHANGELOG.md` following
[Keep a Changelog](https://keepachangelog.com/). Compatibility follows the
[SemVer policy](docs/architecture/semver-policy.md).
