## 1. Context

Доменные спеки экосистемы готовы (plans/flex, B-10..B-26 + волна W2 в работе), реальный
код `corex/*` начат (packages/core,auth,crm,tasks). Эта волна спускается на уровень
КОДА: как называются и устроены модули и компоненты (file-by-file), как ставятся
и обновляются, какие таблицы нужны их инфраструктуре, как продукты собираются из
общих частей (FlexStore = FlexCMS + commerce-модуль; всё — на CoreX). Отдельная
фаза — лицензирование: Битрикс-модель «ключ + домен + срок» для продуктов и модулей,
надёжная активация (ключ нельзя сгенерировать), маркетплейс выдаёт ключи. Критично:
серверная сторона лицензий/дистрибуции УЖЕ спроектирована в RegHub
(Installation_Distribution_Spec: Entitlement API activate/check/deactivate,
update-гейтинг, revocation; ADR-006 RegHub supersedes CoreX ADR-015) — волна проектирует
КЛИЕНТСКУЮ сторону и стык, не переизобретая сервер. Цель — «идеально гармоничная
система» одним планом, а не отдельные планы на подсистемы: компоненты легко
расширяются и настраиваются (Битрикс-лёгкость через визуальный редактор) при строгой
типизации Laravel (стек D4: Filament 5/Livewire + Inertia 3 + Vue). Это план
ПРОЕКТИРОВАНИЯ паттернов, не разработки: выход — C-спеки уровня «дешёвая модель
реализует без вопросов». Артефакты: `plans/flex/30_blueprints/C-XX_*.md` +
`plans/flex/20_research/R-30+`.

## 2. Execution Rules

### Cold-start протокол — каждый item = свежая сессия (D5)

Пользователь сбрасывает контекст перед КАЖДЫМ item'ом. Запуск:

1. `/clear`
2. `/model claude-fable-5` (P1–P7.2) · sonnet (P7.3)
3. `/task:plan-exec FLEX-CODE Pn.m` — Pn.m берётся из **Next** в `handoff.md`

Sonnet-пин текста команды /task:plan-exec переопределён Routing §3 этого плана:
модель уже выбрана на шаге 2, исполнитель её НЕ переключает. Порядок чтения при
холодном старте — строго протокольный: plan.md → handoff.md → phases/Pn.md
(Phase Context + свой item) → Required Reads item'а по списку. **Ни один item не
полагается на память предыдущей сессии**: всё межitem'ное состояние живёт в файлах —
C-спеки (правятся по месту), реестры открытых вопросов внутри спек, handoff.md.
Не хватает контекста, которого нет в Required Reads, — дефект плана: эскалация,
не самодеятельный поиск по репо.

### Общие правила

- **Волна — чистое ПРОЕКТИРОВАНИЕ** (артефакты в `plans/`); реальный код `~/projects/packages/corex` читается read-only, НЕ правится; запись в реальный vault — вне волны (отдельным решением после P7).
- Один item за раз; статус обновляется В ПЛАНЕ (Phase Status + Status Board здесь) до завершения работы.
- Статусы — 6 канонических строк байт-в-байт (⬜ Not started · 🟡 In progress · 🟢 Done · 🟠 Done with deviations · 🔴 Blocked · ⛔ Skipped by decision).
- Решения программы (00_MASTER_PLAN §3 D1–D17, D-001..D-006) и канон RegHub — НЕ пересматривать; противоречие → эскалация (Escalation Needed + 🔴).
- Все research-факты — только через RAG (`.ai/guidelines/perplexity-mcp.md`); без источника → `[UNVERIFIED]`.
- Каждая C-спека несёт секцию «Место в целом» (как артефакт вписывается в карту C-01) и реестр открытых вопросов с адресацией «решён / уходит в C-XX / эскалация»; P7.1 проверяет сквозной реестр.
- Волна FLEXCRM-W2 живёт параллельно (продуктовые домены); её артефакты B-27+ учитывать как канон в момент чтения, конфликты — эскалация.
- После закрытия item/фазы — перезаписать `plans/FLEX-CODE/handoff.md` целиком.
