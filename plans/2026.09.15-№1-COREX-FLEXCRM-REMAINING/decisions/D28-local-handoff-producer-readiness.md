# D28 — handoff-only pending producer metadata

During P3.2 closure, global plan lint treats the partial P3.7 seal as ready because its six explicit branch filenames lack native producer labels and the first two reports now exist. Four actual branch reports still do not exist and their owning P3.3–P3.6 are Not started. Preserve original P3.7 spec in artifacts/B-P3-LOCAL/P3.7-before-pending-producer-annotation.md. For the required B-P3-IDENTITY handoff only, annotate the same six Inputs with exact existing P3.1–P3.6 producers, using native numbered entries. No source, required read, limit, validation, deliverable or scope changes. This makes pending dependency state mechanically honest. P3.7 budget/per-read/selector diagnostics remain mandatory when its producers are GREEN; no advisory scope is extended beyond P3.1/P3.2 and no future product execution/admission is authorized. Runtime unchanged. Reseal this finite plan-owned preparation correction; leave P3 open and stop product execution at P3.2.

Native admission attaches producer edges to missing Required Reads, not Inputs. Therefore the same labels also appear on the six explicitly named Required Reads; the original generic “declared actual branch reports” is expanded into its exact existing six carriers. Canonical numbered declarations also expand the original six-spec range and exhaustive P2 catalogue section selectors, preserving full original source semantics and per-read limits. No branch source is removed, no future Validation/runtime item executes. Missing P3.3–P3.6 producer reports hold P3.7 pending; its actual budget/limits must still pass at future admission.

## Решение

Сохранить принятое выше scoped решение и его исходную owner provenance без расширения полномочий.

## Почему

Явные обязательные разделы и null metadata нужны текущему native генератору decisions; исходный принятый текст сохранён выше, исходные bytes/digest архивированы отдельно.
