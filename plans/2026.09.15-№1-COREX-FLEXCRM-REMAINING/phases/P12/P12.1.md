### P12.1 — Починить контракт модуля, утечку ядра и незаявленные зависимости

**Intent:** Устранить три P0: класс модуля `corex/intl`, не соответствующий контракту `CorexModule`; импорт реализации из `corex/tenancy` внутри контракта ядра; cross-package зависимости, отсутствующие в `require`.

**Why:** `ModuleDiscovery` бросает `InvalidManifestException::notACorexModule` для класса, объявленного в `extra.corex.module`, если он не наследует `CorexModule`. Сейчас `IntlModule` его не наследует и ссылается на несуществующий класс `ModuleDescriptor`, поэтому любое приложение с установленным `corex/intl` падает на discovery. Этот дефект не нашёл ни один из двух аудитов. Две другие правки снимают ложную зависимость контракта ядра от чужой реализации и приводят объявленные `require` в соответствие с фактическими импортами, без чего гейт P12.3 не может быть зелёным по существу.

**Scope Included:** Замена тела `IntlModule` на корректный `manifest(): Manifest` по §1.1 дизайна; удаление импорта `StanclTenancyManager` из контракта ядра и замена docblock-ссылок текстовой формулировкой по §1.2; добавление фактических зависимостей в `require` двух пакетов по §1.3 с соответствующими записями `repositories`; проверка отсутствия других утечек ядра командой из §1.2.

**Scope Excluded:** Перенос `StanclTenancyManager` в ядро; добавление любого `corex/*` в `require` ядра; развод расщеплённого неймспейса `CoreX\Tenancy\` (остаётся объявленным legacy-исключением P12.3); `tablePrefix()` в манифесте `corex/intl`; изменение `extra.laravel.providers`; любое изменение миграций; правка пакетов вне названных; создание гейта — это P12.3.

**Inputs:** `research/P12-rebaseline-design.md` §1 как единственный источник кода; `research/P12-audit-reconciliation.md` пункты NEW-1, A2, A2a, A2b, A3 как вердикты; `decisions/D41-package-boundary-rebaseline.md` как разрешающее решение. Фактический характер использования `CoreX\Wakeup` устанавливается командой из §1.3 в момент исполнения, а не предполагается.

**Files:** `packages/intl/src/IntlModule.php`; `packages/intl/composer.json`; `packages/core/src/Tenancy/Contracts/TenancyManager.php`; `packages/tasks-workflow/composer.json`. При подтверждении требования по §1.3 — `packages/tenancy/composer.json`. Корневой `CHANGELOG.md` под `[Unreleased]`. Собственный append-only journal и генерируемые state/status/проекции.

**Required Reads:** plan.md; decisions/D4.md; decisions/D6.md; decisions/D41-package-boundary-rebaseline.md; research/P12-audit-reconciliation.md; research/P12-rebaseline-design.md; research/P12-design-rag.md; docs/dev-doctrine.md; packages/modules/src/CorexModule.php; packages/modules/src/Manifest.php; packages/modules/src/Discovery/ModuleDiscovery.php; packages/media/src/MediaModule.php; packages/intl/src/IntlModule.php; packages/core/src/Tenancy/Contracts/TenancyManager.php; packages/core/src/Tenancy/TenantContext.php; tests/Arch/LayerTest.php. `packages/media/src/MediaModule.php` читается как рабочий эталон корректного модуля.

**Implementation Rules:** Перед мутацией `python3 plans/2026.09.15-№1-COREX-FLEXCRM-REMAINING/scripts/validate-p12.py --check design` даёт exit 0. D6 — нейтральные внешние запросы. Код берётся только из §1 дизайна; копировать PHP из `audits/*` запрещено, там есть невалидные примеры. `tablePrefix()` не вызывается: паттерн `Manifest` допускает 2–3 строчные буквы, а таблицы пакета используют префикс `corex_`, поэтому любое значение было бы ложью о схеме. Импорт `StanclTenancyManager` используется только в docblock — удаляется вместе с заменой `{@see ...}` на текст, без переноса классов. Версии внутренних зависимостей — `"@dev"`; при наличии блока `repositories` добавить `{"type": "path", "url": "../<пакет>"}`. Правило `require` против `suggest`: импорт на пути выполнения без охраны `class_exists()`/`$app->bound()` — это `require`; охраняемый импорт с рабочим fallback остаётся `suggest` и обязан попасть в allowlist гейта P12.3 с указанием файла-охранника. Каталоги миграций не трогаются.

**Code Guidance:** §1.1 дизайна содержит готовый файл `IntlModule` целиком — взять как есть. §1.2 задаёт точную процедуру удаления импорта и проверочную команду отсутствия других утечек. §1.3 содержит таблицу «пакет → добавить в require → причина» и команду установления характера использования `CoreX\Wakeup`. Инварианты стиля из §0 дизайна: `declare(strict_types=1);`, `final`, `#[Override]`, явные типы. Существующий `MediaModule` показывает целевую форму манифеста.

**Validation:** `cd packages/intl && composer test && composer analyse && composer lint:check`; то же для `packages/core` и `packages/tasks-workflow` после появления скриптов в P12.2 либо через корневые `composer analyse` и `composer test:arch`. Обязательно наблюдаемое доказательство, что discovery больше не падает: прогон, в котором `ModuleDiscovery` обрабатывает `corex/intl` без `InvalidManifestException`. Команда из §1.2 печатает `clean`. `bash scripts/anti-weakening-gate.sh` зелёный. `git diff --stat -- 'packages/*/database/**'` пуст. Отсутствие доступного pg-лейна раскрывается как ограничение окружения с перечислением непокрытых групп, а не как зелёный результат.

**Deliverables:** `corex/intl` проходит discovery; контракт ядра не ссылается ни на одну реализацию из другого пакета; объявленные `require` соответствуют фактическим импортам, а осознанно оставленные `suggest` перечислены с файлами-охранниками для allowlist P12.3. Запись в `CHANGELOG.md` под `[Unreleased]`. Receipt с фактическим выводом команд и явным указанием непокрытых групп.
