# P2 — Минимальные reusable contracts и границы адаптеров

## Phase Context

P2 детализирована четырьмя contract-catalogue items. Дизайн использует доступные R/AC/A/E/source
и будущие producer **contracts**; actual P1 GREEN и G-SOURCES нужны при исполнении, не выдуманы.
P2 не изменяет library API/DDL/dependencies или чужие системы: выпускает квалифицированный
catalogue и exact proposed bytes/owner requests. Local catalogue acceptance отличается от
protected adoption и effective deployment. P3–P8 дизайн может определить exact candidate shape
до выполнения P2; P2.3 читает immutable specs, не runtime outputs, поэтому execution DAG не цикличен.

**Обязательный design gate D4/D5/D6:** Perplexity проверяет только общие лучшие практики,
конкретные технические вопросы и публичные примеры. CoreX — внутренняя разработка: не спрашивать
Perplexity про её устройство/API/gaps/state, не передавать внутренний контекст как предмет поиска.
Нейтральный P2 query успешен; raw result/digest, independently checked primary sources,
alternatives/limits сохранены в research/P2-design-rag.md. Внутренние facts — RAG:— локально.
До product mutation любого item: scripts/task-check.py --check design exit 0; все P1–P11 detailed
и whole-plan finish обязателен. Сейчас P3–P11 skeleton, P2 items Not started.

## Scope Included

existing-vs-equivalent-versus-minimal-gap; typed exact API/DTO/enum/error/version/BC/schema/source

conditional phase edges и precise gate requests с named owners/resume. D7 owns decomposition.

## Scope Excluded

Library/consumer runtime/API/DDL/dependency/source changes; global ID or tenancy rewrite, new
extender/event/auth/CRUD engine; actual central/cloud target acceptance/deployment; public/private
publication; foreign plans/sources/product milestones. Названия из legacy blueprint не дают scope.
