## Проверка при каждой детализации и при finish

- R01–R52/365 parent criteria сохраняются; product/standalone/central/cloud owners не перемещаются в CoreX.
- Каждый новый порт соответствует конкретному gap и non-CRM consumer; A01–A09/8 extenders/API SPI сохраняются.
- Для каждого phase edge: producer path/schema/version/acceptance receipt → consumer Required Reads/behavior;
  dependencies не образуют cycle; unavailable future artifacts имеют contract, не fabricated bytes.
- Storage/identity/clock/wakeup/access/transport contexts согласованы; errors/unknown commit/idempotency
  и retry/crash/restore semantics одинаковы на соединяемых границах; optional provider отсутствие явно проверено.
- P2 signatures/BC/schema proposals ↔ P3–P8 implementations ↔ P9 release cohort ↔ P10 actual DI/AP
  ↔ P11 immutable consumer pins/outcomes связаны одним набором R и compatible versions.
- Perplexity/primary sources поддерживают каждый ключевой choice; alternatives и rejected options
  с причинами видны всем фазам; конфликт разрешается до finish, не молчаливым предположением исполнителя.
- Pre-mortem: потеря tenant/context scope, stale authorization, ambiguous replay/restore, circular producers,
  duplicate engine, changed release cohort и missing external receipts: для каждого mitigation + owner + check.
- Design gate подтверждает полноту/hash freshness; semantic integration review и actual runtime tests
  остаются отдельными obligations. GREEN дизайна не release/live/consumer acceptance.
