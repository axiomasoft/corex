## Schema, name and revision profile

**tool-schema/1:** JSON Schema2020-12 (explicit $schema), root object for args and result for baseline MCP2025-11-25 profile. Local nonrecursive $defs and $ref closure, type/object/array/string/integer/number/boolean/null, enum/const, properties/required/additionalProperties/unevaluatedProperties, items/prefixItems/min/maxItems, min/maxProperties, min/maxLength, pattern, minimum/maximum/exclusive bounds/multipleOf, allOf/anyOf/oneOf/not/if/then/else accepted only by qualified evaluator. Annotation fields title/description/default/examples/readOnly/writeOnly/deprecated/format are documented, never authority/default injection/coercion. Unsupported keyword, $dynamicRef, $dynamicAnchor, recursive reference graph, custom vocabulary/extensions rejected as local policy; no changes to JSON Schema standard fallback. No extensions that fetch files, PHP objects, evaluate custom code, cast/filter values or mirror authority headers. Domain semantic format checks remain owning module. additionalProperties obeys **same subschema** semantics, not a union rewritten by generic code; unevaluatedProperties uses successful evaluator annotations. Opis JSON Schema2.x is source candidate from official docs; exact available compatible version/ref/license/upstream tests must be qualified P8.1 then approved G-DEPENDENCY/P2, never assume current lock installs it or full draft conformance. Optional composer suggest/dev test dependency and Internal\OpisToolSchemaValidator adapter require same exact adopted source; no root eager optional resolution. Missing engine on enabled tools fails closed, baseline boot independent.

JSON tree preserves object/map vs list/array, including empty and numeric-key objects; reject duplicate keys, nonfinite/over-safe-range numbers and decoding loss (safe integer bound ±9007199254740991, numeric precision contract source-qualified). Financial/large exact values represented by owner decimal strings. JSON Schema integer is mathematically integral, e.g.1.0 is integer if representable; do not invent a lexical-integer requirement. Handler mapping after validation preserves nested object/list via typed JsonObject/JsonValue in Api\Data; domain adapter explicitly maps to accepted array DTO representation and must reject any semantic loss. Never hash lossy associative arrays. Typed argument digest includes operation defaults/domain version if effect uses them, using qualified canonical JSON mechanics compatible with owner guard (RFC8785 only safe numeric profile; existing owner key model retained).

Limits frozen local policy: schema131072bytes,128resources,depth32,4096schema nodes; args/result131072bytes,depth32,4096members/items aggregate;regex256bytes;16returned errors;catalogue1000descriptors. Schema admission and instance evaluation execute in an isolated validation-only subprocess with a hard100ms deadline and64MiB memory budget; its supervisor returns schema_limit on deadline/memory failure and never admits a partial result. Bounds include regex/evaluator work even when the upstream library lacks an internal visit counter. Domain handler/effect never executes in or is killed with that subprocess. Qualification must prove timeout/memory/crash/cleanup/no-network enforcement. No unsupported internal iteration hook is assumed, and measuring wall time after unbounded evaluation is insufficient. Consumer may narrow; widening changes profile/hash and requires same decision/adoption process.

## Invocation order, failures and transport boundary

Fresh trusted context/authentication at transport owner → exact descriptor/current activation/discover+invoke policy → bounded schema admission/input validation → explicit domain scoped resource checks → consumer execution guard (proof/claim/idempotency) → current checks+owning Action+output validation callback → current result visibility+typed outcome → transport projection. Generic check plus callback check reduces window; final domain transaction/optimistic resource/authority predicate is mandatory. External effects use durable owner operation/outbox then provider-key/status reconciliation, not pretend one DB lock controls network.

ToolResult final readonly: outcome=not-executed/committed/unknown; structuredData JsonObject?; errorCode?; operationKey?; replayed bool. Safe errors tool_unavailable,context_required,forbidden,input_invalid,schema_unavailable,schema_limit,catalogue_limit,tool_revision_conflict,approval_required,approval_invalid,idempotency_conflict,in_progress,unknown_effect,output_contract_failed,internal_error. No blind retry metadata. Known domain conflict preserved by explicit adapter, no SQL guessing. Invalid output in local callback rolls back with same domain transaction; external commit can be committed+output_contract_failed or unknown, no fabricated rollback. Replayed result requires current response visibility. Guard must persist exact result/outcome while reserving effects under owner local schema; no generic tables here. No unguarded draft/write/irreversible invocation even from internal fake transport. Strong double confirmation for irreversible carried by consumer policy; generic class never interprets approved_by as authority.
