# D10 — Модели Cursor под классы маршрутизации

**Actor:** plan-designer/frontier/high
**Evidence:** RAG:✅ 2026-09-19 — документация Cursor (Models & Pricing, страницы моделей,
Help Center): тарификация токенная по ставкам провайдеров без наценки; первопартийные модели
освобождены от Cursor Token Rate ($0.25/M на Teams/Enterprise для сторонних). Ставки за млн
input/output: Composer 2.5 $0.5/$2.5 (Fast $3/$15); Grok 4.6 $2/$6, уровни усилия
`xhigh`/`high`/`medium`/`low`; Claude Sonnet 5 $2/$10, thinking, «strong default for everyday
coding»; Claude Opus 5 $5/$25, «strong at planning and tool use», до 1M контекста без доплаты;
GPT-5.6 Sol $4/$20, промо до 21.11.2026, удвоенный input свыше 272k; Gemini 3.1 Pro $2/$12,
доплата свыше 200k; Claude Fable 5.1 $10/$50.
RAG:— рекомендации «модель X для архитектуры» в документации нет; ближайшее — «быстрые модели
для рутины, более способные для сложных рассуждений и многофайлового рефакторинга».

## Решение

| Класс/усилие | Модель Cursor | in/out за млн | Где |
|:--|:--|:--|:--|
| frontier/high | Claude Opus 5 (thinking, high) | $5 / $25 | P1, P4, P5, P13, P14 |
| frontier/high | Grok 4.6 (effort `high`) | $2 / $6 | P2, P3, P6, P9, P10, P11, P12, P17 |
| implementation/high | Claude Sonnet 5 (thinking) | $2 / $10 | P7, P8, P15, P16 |
| implementation/medium–high | Composer 2.5, стандартный тир | $0.5 / $2.5 | исполнение всех items |

- Items исполняются стандартным Composer 2.5, не Fast: Fast в шесть раз дороже на output и
  предназначен для интерактивных сессий, а items — длинногоризонтная работа по готовой спеке.
- Для design-проходов не использовать GPT-5.6 Sol, Gemini 3.1 Pro и Claude Fable 5.1: у первых
  двух доплата за длинный контекст (порог 272k и 200k), промо-цена Sol истекает 21.11.2026;
  Fable 5.1 вдвое дороже Opus 5 без задокументированного преимущества для этой работы.
- На Teams/Enterprise сторонние модели несут Cursor Token Rate $0.25/M, первопартийные Grok и
  Composer — нет. Это усиливает Grok 4.6 как дефолт, но не меняет Opus 5 на пяти фазах.
- Смена модели внутри класса допустима (разведка дешёвой, финальный дизайн более способной);
  смена класса вниз запрещена.

## Почему

Цена design-прохода определяется output'ом: проход производит `research/Pn-design.md` с готовым
кодом и item-спеки — десятки тысяч выходных токенов при умеренном и частично кешируемом input'е.
$25 против $6 за млн output — четырёхкратная разница при сопоставимой пригодности там, где нет
необратимого контракта.

Opus оставлен там, где ошибка не локальна: P1 воспроизводится в 16 фазах; P4 и P5 меняют
durable-границу и гарантии доставки; P13 замораживает внешний контракт; P14 несёт исходящие
необратимые эффекты и подписи. Экономия $2–4 за проход этого риска не оправдывает. Дополнительный
аргумент — отсутствие доплаты за длинный контекст до 1M: при компактизации сессии цена не прыгает.

P7, P8, P15, P16 не содержат открытого дизайна: правила приняты в P1, проход транскрибирует их в
спеки (типизированная конфигурация по одному шаблону, декомпозиция провайдеров без смены
поведения, ренеймы по утверждённому реестру, перемещения по утверждённым профилям). Sonnet 5 в
thinking-режиме для этого достаточен.

Альтернатива «всё на Composer 2.5» отклонена: тогда исполнитель items сам пишет себе спеки, и
гарантия «в спеке лежит готовый код» перестаёт быть независимой. Альтернатива «всё на Opus 5»
отклонена как переплата примерно вчетверо на двенадцати проходах из семнадцати.

## Consequences

`plan.md` §3.3 несёт эту таблицу. Ориентир порядка стоимости прохода (input ≈ 150–300k с кешем,
output ≈ 30–60k): Opus 5 ≈ $2–4, Grok 4.6 ≈ $0.7–1.2, Sonnet 5 ≈ $0.8–1.5; item на Composer 2.5
≈ $0.2–0.4. Это порядок величины, а не смета: зависит от длины сессии и доли кеш-попаданий.
