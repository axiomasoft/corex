# D4 — Публичная поверхность контролируется машинно, а не рукописным списком символов

**Actor:** plan-designer/frontier/high
**Evidence:** RAG:✅ 2026-09-19 — `roave/backward-compatibility-check` 8.22.0 (2026-09-16)
сравнивает публичный API двух ревизий; PHPStan поддерживает enforcement `@internal`
(2.1.13+/bleeding edge); `tomasvotruba/class-leak` обнаруживает случайно публичные классы;
`api-diff` — не PHP-инструмент.
RAG:— в дереве нет ни одного `api/public.php`; `scripts/contract-guard.sh` — warn-прокси,
требующий записи в CHANGELOG при диффе `src/Contracts/**`, без BC-анализа.

## Решение

Публичная поверхность пакета фиксируется тремя носителями, ни один из которых не является
рукописным перечислением всех символов:

1. `extra.corex.public-api` — список публичных **неймспейсов** пакета (D3);
2. `@api` / `@internal` в исходниках плюс enforcement статическим анализом;
3. release-to-release BC-дифф в CI как условие тега.

Уровни стабильности — `stable | experimental | internal | deprecated`, объявляются на символе
и агрегируются в `extra.corex.stability` пакета.

## Почему

Рукописный `api/public.php`, предложенный аудитом, неизбежно расходится с кодом: он не
проверяется компилятором, не обновляется при рефакторинге и создаёт третий источник правды
поверх namespace и docblock'ов. Перечисление неймспейсов, наоборот, стабильно и проверяемо
автоматически, а BC-дифф отвечает на реальный вопрос релиза — «сломали ли мы потребителя», —
на который список символов не отвечает вообще.

Существующий `contract-guard.sh` не отменяется: он остаётся дешёвым warn-гейтом на диффе
контрактов и дополняется настоящим BC-анализом.

## Consequences

P1 формулирует политику и заполняет `public-api`; P3 добавляет гейты (`@internal`, BC-дифф,
запрет импорта не перечисленных неймспейсов); P13 обязана держать snapshot'ы схемы внешнего
API отдельно от BC-диффа PHP-символов — это два разных контракта; P17 делает BC-дифф условием
тега 1.0. Вводится dev-зависимость (BC-чекер) — единственная разрешённая этим решением.
