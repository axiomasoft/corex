### P1.3 — Гид имён и реестр переименований

**Intent:** Создать `docs/architecture/naming.md` (критерий пригодности суффикса, словарь из двенадцати суффиксов с границей исключения, перечень не вводимых имён, правила имён идентификаторов/булевых/коллекций) и `docs/architecture/rename-registry.md` — реестр из 27 переименований «сейчас → целевое → пакет → фаза → условие».

**Why:** Словарь имён нигде не записан, а в дереве уже есть имена с расходящейся семантикой (`RAG:—`, A08): `Dep` с полями `$type`/`$target`, 18 каталогов `Data`, `Manager`/`Resolver` в разных значениях. При этом предложенный аудитом запрет `Helper`/`Util`/`Processor`/`Misc`/`Common` бьёт по именам, которых в дереве нет вовсе (0 совпадений), то есть был бы декларацией без предмета. `RAG:✅` суффикс осмыслен только тогда, когда даёт и положительный контракт, и границу исключения — то есть отвечает, что в класс добавлять нельзя; перечисленные generic-имена — запахи, а не запреты, и у каждого есть названный легальный случай (`research/P1-design-rag.md` §1, запрос P1-Q8). Реестр переименований создаётся здесь, потому что по D1 имена меняются только после фиксации семантики, и один реестр лучше, чем решение «переименовать по ходу» внутри item'а каждой фазы.

**Scope Included:** Файл `docs/architecture/naming.md`: раздел «суффикс обязан что-то запрещать» с трёхшаговой проверкой, таблица двенадцати суффиксов в форме «класс обязан / класс не вправе», таблица имён, которые не вводятся, с колонкой легального случая, раздел правил имён идентификаторов, булевых, коллекций, отображений, единиц измерения и случаев enum, правило скоупа гейта «только публичные сигнатуры». Файл `docs/architecture/rename-registry.md`: таблица 27 строк с колонками «Сейчас / Целевое / Пакет / Фаза / Условие / Источник» плюс явное правило «реестр не исполняется в P1». Строка в корневом `CHANGELOG.md`.

**Scope Excluded:** Любое фактическое переименование класса, метода, свойства, файла, каталога, неймспейса, конфиг-ключа и artisan-сигнатуры (D1, `NON-001`) — этот item только описывает; изменение любого PHP-файла; создание гейта словаря имён (P3); решение Q1/Q2 о переименовании пакетов `corex/api` и `corex/auth` — строки реестра фиксируют их как требующие владельца; правка `packages/**`; добавление в реестр имён, которых нет в дереве.

**Inputs:** `research/P1-design.md` §5 как нормативная спецификация: §5.1 готовый текст критерия, §5.2 словарь суффиксов, §5.3 таблица не вводимых имён с легальными случаями, §5.4 готовый текст правил имён, §5.5 готовая таблица реестра из 27 строк с правилом сверки по дереву; `research/P1-design-rag.md` §1 (запрос P1-Q8) как внешнее подтверждение критерия; `findings/audit-verdicts.md` A08, A42–A46, A50, A59, A62, A63, A67, A68, A70, A71, A72, A77–A82 как источники строк; `docs/architecture/constitution.md` как владелец статьи `API-009`; `open-questions.md` Q1, Q2 как статус двух строк реестра.

**Files:** `docs/architecture/naming.md` (новый); `docs/architecture/rename-registry.md` (новый); `CHANGELOG.md` (строка под `[Unreleased]` → `### Added`).

**Required Reads:** 1) `phases/P1/P1.md`; 2) `research/P1-design.md` §0, §5, §13; 3) `research/P1-design-rag.md` §1; 4) `decisions/D1-normative-before-moves.md`; 5) `findings/audit-verdicts.md` §6 и §4; 6) `open-questions.md` Q1, Q2; 7) `docs/dev-doctrine.md` §3, §4; 8) `docs/architecture/constitution.md`; 9) `packages/modules/src/Dep.php`; 10) `packages/search/src/SearchManager.php`; 11) `packages/api/src/Dispatcher.php`.

**Implementation Rules:** Перед записью каждой строки реестра исполнитель проверяет существование исходного имени командой `rg -l "<ИмяКласса>" packages/<pkg>/src`. Несуществующее имя из реестра удаляется, и факт удаления попадает в receipt — реестр, ссылающийся на несуществующий класс, гниёт с первого дня. `RecordRules` в реестр не вносится: класс с этим именем живёт в `packages/crm/src/Support/`, а предложение аудита касалось `corex/auth`, где его нет (`RAG:—`, A71 опровергнуто). Строка `WhyCommand` → `ExplainModuleCommand` обязана нести в колонке «Условие» явное «сигнатура artisan `corex:modules:why` сохраняется» — иначе P15 сломает публичный интерфейс команды. Строка `TasksWorkflowModule` → `TaskWorkflowIntegration` обязана нести «идентификатор модуля (composer-имя) не меняется» (D82). Строки о переименовании пакетов `corex/api` и `corex/auth` несут в колонке «Условие» слова «решение владельца Q1/Q2» и не получают даты. Перечень не вводимых имён составляется только из фактически встречающихся (`Dep`, `*Info`, `Manager`, `Service`, `Data`) плюс профилактический блок имён с нулём совпадений, и это различие объявлено в документе: гейт P3 будет проверять появление нового имени, а не существующее состояние. Словарь суффиксов пишется в форме «класс обязан / класс не вправе»: вторая колонка несущая, без неё суффикс не даёт границы. Ни один файл вне `Files` не изменяется.

**Code Guidance:** Готовый текст раздела о критерии — `research/P1-design.md` §5.1, переносится дословно вместе с трёхшаговой проверкой. Таблица суффиксов — §5.2, все двенадцать строк. Таблица не вводимых имён — §5.3, вместе с колонкой легального случая и с пояснением про `SearchManager` как существующий легальный случай суффикса `Manager`. Правила имён — §5.4, переносятся как есть, включая правило о том, что гейт применяется только к публичным сигнатурам. Реестр — §5.5, все 27 строк с сохранением колонок и источников. Заключительный абзац §5.5 про `RecordRules` переносится в документ как примечание, чтобы опровергнутое предложение не вернулось.

**Validation:** Число строк таблицы в `docs/architecture/rename-registry.md` равно числу фактически внесённых строк (27 минус удалённые по сверке, с перечислением удалённых в receipt). Для каждой строки реестра исходное имя существует: проход по колонке «Сейчас» с `rg -l` в указанном пакете даёт ноль промахов. Каждая строка реестра имеет непустую колонку «Фаза». Две строки о переименовании пакетов имеют в колонке «Условие» ссылку на Q1/Q2. `rg -c "не вправе" docs/architecture/naming.md` больше нуля — колонка границы присутствует. `git diff --stat -- 'packages/'` пуст: ни одного переименования не выполнено. `composer lint:check` из корня — зелёный. `composer test:arch` — зелёный.

**Deliverables:** `docs/architecture/naming.md` с критерием пригодности суффикса, словарём двенадцати суффиксов, перечнем не вводимых имён с легальными случаями и правилами имён; `docs/architecture/rename-registry.md` с проверенным по дереву реестром и явным правилом «в P1 не исполняется»; запись в корневом `CHANGELOG.md`. Receipt — append к `findings/P1-receipts.md`: результат сверки каждой строки реестра с деревом и перечень строк, удалённых как несуществующие.
