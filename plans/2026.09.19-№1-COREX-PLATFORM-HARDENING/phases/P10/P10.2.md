### P10.2 — Stable identity и canonical snapshot

**Intent:** Ввести UUIDv7 identity, immutable revision/lifecycle и canonical definition,
не ломая форму существующего `FieldSnapshot`.

**Why:** `P10-design.md` §2; D50. Key не переживает rename, а identity отсутствует.

**Scope Included:** additive public data types; snapshot rows/hash; module mapping;
legacy UUIDv5 bridge и pinning rule; validation tests.

**Scope Excluded:** DB DDL/source; backfill runtime; public renames P15.

**Inputs:** `phases/P10/P10.1.md`; `research/P10-design-rag.md`;
`packages/core/src/Enums/IdStrategy.php`;
`packages/attributes/src/Internal/Registry/RegistryFieldCatalogue.php`.

**Files:** `packages/attributes/src/Data/AttributeId.php`;

**Implementation Rules:** New definitions require explicit UUIDv7. Legacy UUIDv5
is deterministic and flagged, never accepted for rename/evolution. Keep `code=key`;
canonical maps sorted recursively; snapshot stable across source order.

**Code Guidance:** Constructors and enum shape are normative in §2.1. Use `Str::uuid7()`
and a fixed documented UUIDv5 namespace; no dependency.

**Validation:** Reject non-v7 new ids, duplicate key/id, invalid transition; prove
same input gives same hash and key rename retains pinned id.

**Deliverables:** Identity/model types, compatible snapshot, module mapper and tests.
