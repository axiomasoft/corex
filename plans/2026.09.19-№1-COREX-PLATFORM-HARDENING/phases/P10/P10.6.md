### P10.6 — Восемь write checks

**Intent:** Сделать каждый слой write authority и validation отдельным, fail-closed
и наблюдаемым без утечки существования скрытого поля.

**Why:** `P10-design.md` §7–§8; D54. Текущий общий action недостаточен.

**Scope Included:** `expectedSchemaHash`; ordered guard; opaque resource/action mapping;
constraints; atomic batch behavior; eight negative test families.

**Scope Excluded:** P13 operation contract/onlyFields; новый authorization interface;
изменение public store methods.

`packages/core/src/Contracts/DataScopeAuthorizer.php`;

**Implementation Rules:** Fixed order from §8. Authoritative uncached snapshot.
External denial normalised; internal reason distinct and value-free. Migrating or
deprecated write requires matching hash. Batch mutation is all-or-nothing.

**Code Guidance:** Build canonical resource from scope/entity/opaque record id/attribute
id; no model FQCN. Keep type vs constraint validators distinct.

**Validation:** One red test per check plus hidden-vs-unknown same external error;
wrong tenant before DB mutation; stale hash; batch rollback; both engines.

**Deliverables:** Patch precondition, guard/validator, store wiring, negative matrix.
