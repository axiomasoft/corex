# P10 — Attributes: независимые определения и безопасная эволюция

## Phase Context

`RAG:—` Текущий `FieldCatalogue` уже является нужным портом, но его единственная
полезная реализация требует одновременно `EntityRegistry` и `ModuleRegistry`.
Хранилища JSONB/EAV сменные, а определения полей и глобальный выбор хранилища — нет.

`RAG:✅` P10-Q1: UUIDv7 стандартизован RFC 9562 и поддержан `Str::uuid7()`;
он совпадает с фактическим default ADR-003. P10-Q2: безопасная смена живой схемы
требует expand/synchronise/backfill/verify/contract. P10-Q3: PostgreSQL различает
GIN для содержимого JSONB и B-tree для упорядоченного вывода; expression/partial
индексы полезны только при совпадении с реальным запросом.

> **Контракт фазы.** Потребляет: `DataScope` P4, outbox/envelope P5,
> typed composition P7. Производит: attributes без modules, стабильную identity
> определения, авторитетный composite catalogue, ревизии и обратимый backfill,
> resolver хранилища по entity, измеренную index policy, восемь write checks и
> сообщение `attributes.values.changed.v1`. Существующие `FieldCatalogue` и
> `AttributeStore` не ломаются; зависимости attributes→search нет.

> **Phase Assurance | v1.**
> Impact: public-contract
> Integration Seams: field-catalogue · attribute-store · tenant-database · schema-operations · message-outbox · authorization
> Live or Irreversible: yes
> Audit Intent: direct-close-eligible
> Rationale: определения и значения живут в tenant DB; P10.3–P10.7 имеют `full`
> review, обратимый путь и PostgreSQL-доказательство. Единственный DDL-owner — P10.3.

## Scope Included

Static/module/database/composite/cached реализации существующего `FieldCatalogue`;
UUIDv7 `AttributeId`; immutable revisions; lifecycle `draft|active|deprecated|migrating|retired`;
expand/dual-write/backfill/verify/contract; entity-level storage resolver; JSONB/EAV;
`none|expression_btree|promoted` index policy; восемь write checks; outbox contract
без значений; subsystem-layout `Schema/Values/Query/Storage/Integration/Laravel`;
negative graph/config/authorization/index fixtures; root changelog и receipts.

## Scope Excluded

Новый порт вместо `FieldCatalogue`; новый subject DTO вместо `RecordRef`; выбор
storage на поле; переписывание `QueuedSchemaOperations`; generic workflow engine;
автоматическая генерация DB identity из key; GIN «на всё»; создание колонок в
таблицах других пакетов; зависимость attributes→search; переименование public
символов P15; изменение контрактов P13 `onlyFields`.

## Dependencies

P4, P5 и P7 терминальны; стадия 2 закрыта (D14). Внутри:
`P10.1 → P10.2 → P10.3 → P10.4`; после P10.3 параллельно `P10.5` и `P10.6`;
`P10.4 + P10.6 → P10.7`; все → P10.8. P10.3 требует G-DDL owner confirmation.

## Validation

Каждый item: `composer lint`, `composer analyse`, `composer test` пакета и корневой
`composer test:pg`; DB-mutating tests только после test-isolation preflight. P10.8
исполняет `research/P10-design.md` §12, все negative fixtures, проверку zero imports
из `corex/search`, повтор backfill/event delivery и compatibility snapshot. Пропуск
PostgreSQL lane или owner gate не считается green.
