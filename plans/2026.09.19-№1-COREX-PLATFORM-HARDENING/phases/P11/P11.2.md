### P11.2 — Deterministic compiler and canonical frozen snapshot

**Intent:** Нормализовать declarations в compiler-private IR, отклонять
duplicates/invalid replacements и публиковать detached snapshot с одним
canonical SHA-256 fingerprint.

**Why:** `research/P11-design.md` §3–§6; D57. `readonly` массивы с mutable
extender objects не замораживают authority, а insertion order не является
допустимой семантикой.

**Scope Included:** Normal form expansion; point-specific duplicate checks; replacement graph;
default/priority/topological order; canonical bytes; schema/compiler/module provenance;
fingerprint validation; detached hydration.

**Scope Excluded:** Runtime collector freeze; worker refresh; tenant activation; durable payloads;
API profile P13; adding common `priority` to extenders.

**Implementation Rules:** Normalize lists before collision checks. Diagnostics identify point, id
and both owners. Replacement target/replacement must exist in one point; one incoming edge; owner
must own replacement; graph must be acyclic. Use §4 ordering only. Canonical hash is exactly §5;
unknown schema, missing fingerprint and mismatch fail closed. Persist scalar arrays, never shared
mutable extender objects.

**Code Guidance:** Keep IR internal and one-way: manifest → normalized records → validated
effective records → typed slices. Compare canonical arrays/bytes in tests across shuffled module,
declaration and associative-key order; separately preserve semantic lists.

**Validation:** Permutation/property fixtures yield one byte-identical artifact and fingerprint;
negative matrix covers every replacement error, duplicate normalized route/wire identity, menu
missing target/cycle, corrupt/old artifact and attempted mutation isolation; package/root module
lint, analysis and tests.

**Deliverables:** Deterministic compiler, complete diagnostics, canonical fingerprinted snapshot
and proof that hydrated mutations cannot alter authority.
