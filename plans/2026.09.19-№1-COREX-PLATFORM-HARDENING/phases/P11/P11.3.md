### P11.3 — Runtime publication, collector freeze and refresh boundaries

**Intent:** Сделать compiled snapshot единственным runtime authority, закрыть
late mutation entity collector и закрепить request/job/deploy refresh boundaries.

**Why:** `research/P11-design.md` §6–§7; D58. `ArrayEntityRegistry::register()` сейчас
доступен после boot, а introspection считает второй revision hash.

**Scope Included:** Validated snapshot loading; authority fingerprint propagation; entity collector
duplicate/freeze rules; booted freeze; job memo reset/pinning; Octane deploy documentation;
activation epoch kept separate.

**Scope Excluded:** Octane package dependency or hot reload; fleet-wide atomic cutover; tenant-specific
compiled files; second extension lifecycle FSM; durable stamp consumers.

**Implementation Rules:** One request/job reads one snapshot. Existing `JobProcessing` boundary may
clear memo before the job but never swaps during it. Freeze after compiled entity projection and
morph/audit setup. Late or duplicate registration throws before mutation. Introspection returns
the compiled fingerprint. Activation epoch continues to key live tenant state and never enters it.

**Code Guidance:** Preserve `EntityRegistry` read contract; `freeze()` stays implementation-side.
Hydrate from validated scalar snapshot and retain the pinned instance for the unit of work. Document
`octane:reload`/queue restart as deployment obligations without runtime class references.

**Validation:** Tests prove duplicate and late registration leave state/morph map unchanged; two
reads inside a job are pinned while next job reloads; corrupt artifact fails; introspection equals
authority fingerprint; activation changes do not change fingerprint; modules/root feature checks.

**Deliverables:** Frozen entity projection, authoritative introspection, explicit worker refresh
contract and tests without an Octane dependency.
