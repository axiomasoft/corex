### P11.7 — Versioned notification digest wakeups

**Intent:** Перевести notification digest bridge на versioned wakeup definition и
доказать exact-version/legacy behavior без изменения digest semantics.

**Why:** `research/P11-design.md` §11.2; D59. Notifications — второй реальный
wakeup producer/handler; без него contract suite доказывает только
tasks-workflow case.

**Scope Included:** Structured handler declaration `notification-digest/1`; stamped scheduling;
adapter compatibility; explicit bounded legacy fixture; mismatch/no-invocation tests.

**Scope Excluded:** Digest selection/delivery policy; notification DDL; channel drivers; generic
wakeup mechanics; enabling legacy admission by default in production.

**Implementation Rules:** Canonical kind remains `notification.digest.v1`; implementation version
is `notification-digest/1`. New rows are always stamped. Legacy admission is test/config explicit,
bounded to this definition and false by default. Version mismatch/missing stamp never reaches the
adapter; existing digest idempotency/concurrency semantics stay unchanged.

**Code Guidance:** Reuse P11.5 config shape; do not add a notifications-side registry or duplicate
stamp serializer. Assert the adapter receives the same unwrapped payload DTO as before.

**Validation:** Bridge tests cover canonical declaration/stamp, exact match, default-denied legacy,
explicit legacy bridge and version mismatch; PG digest concurrency remains green and proves no
duplicate run; notifications lint/analyse/test and isolated PG lane.

**Deliverables:** Stamped digest scheduling, versioned handler declaration and compatibility/mismatch
proof for the second wakeup consumer.
