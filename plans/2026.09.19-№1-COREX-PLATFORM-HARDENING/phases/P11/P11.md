# P11 — Модель расширения: типизированные реестры, compile → frozen, lifecycle

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается `design-phase: task:plan-design 2026.09.19-№1-COREX-PLATFORM-HARDENING P11`

RAG:— Хорошая новость: God Registry в дереве нет — реестры уже типизированы (`ModuleRegistry`,
`OperationRegistry`, `PanelCatalogue`, драйверы `SearchManager`, `FieldCatalogue`), а
`packages/modules` уже компилирует реестр (`RegistryCompiler` → `CompiledRegistry` →
`CompiledModuleRegistry` с `failIfMissing` в production). Не хватает ровно двух вещей: слова
`freeze` в пакете нет ни разу, и запрета дубликатов идентификаторов нет.

Без заморозки поведение зависит от порядка запросов в долгоживущем процессе; без запрета
дубликатов случайная коллизия имён становится молчаливым переопределением.

RAG:✅ Внешние платформы дают один паттерн: discover/declare → normalize → validate uniqueness →
sort по явным правилам → compile/cache → инвалидация на контролируемых границах lifecycle.
Symfony валидирует и замораживает до обслуживания запросов; равный приоритет не является
механизмом разрешения конфликта, нужен стабильный tie-breaker; Drupal чистит и производные
кеши, не только discovery; Shopware даёт операционный lifecycle и требует идемпотентности по
стабильному техническому ключу, уважая `keepUserData()`. Отдельно подтверждено: durable-решение
должно сохранять id и версию расширения либо fingerprint реестра, иначе повтор джоба может
выполнить другую реализацию.

> **Контракт фазы (contract-first).** Потребляет: форму реестра атрибутов P10, гейты P3.
> Производит: общие инварианты реестра, фазу `frozen` с запретом runtime-модификации,
> детерминированный порядок и duplicate policy, fingerprint скомпилированного реестра,
> сохранение id/версии расширения в durable-решениях, lifecycle расширения и contract suite
> для внешних расширений. Границы: закрытый набор из восьми extenders не расширяется
> (девятый — только через RFC по доктрине); имя каталога `Extend` не меняется.

> **Phase Assurance | v1.**
> Impact: internal-integration
> Integration Seams: module-extension-points · durable-decisions · compiled-registry-cache · long-running-workers
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: Freeze-семантика и fingerprint в durable payload влияют на воспроизводимость
> повторов; Review этих items — `full`.

## Scope Included

Общие инварианты реестра как исполняемый контракт; фаза `frozen` после `compiled` с запретом
или явным ограничением runtime-модификации; детерминированный порядок `priority DESC, id ASC` и
запрет опоры на порядок обхода файловой системы, включения модулей и вставки в массив;
duplicate policy: дубликат идентификатора внутри точки расширения — ошибка компиляции, замена
только через явную декларацию с проверкой существования цели и ацикличности; fingerprint
скомпилированного реестра, покрывающий набор и версии модулей, нормализованные декларации,
версию схемы точки расширения и версию сборки; сохранение id и версии расширения либо
fingerprint'а в durable-решениях (`workflow`, `wakeup`, `tasks-workflow`); lifecycle расширения
(register → validate → activate → execute → deactivate) с идемпотентностью операций по
стабильному ключу и правилом «деактивация не оставляет систему в неопределённом состоянии»;
инвалидация всех производных кешей, а не только discovery; contract suite, который обязано
проходить внешнее расширение; атомарная замена снапшота для долгоживущих воркеров.

## Scope Excluded

Расширение закрытого набора восьми extenders (только RFC по доктрине); переименование `Extend`
и `Gate` (отклонено, A45); создание универсального `register($anything)`; перевод платформы на
event sourcing; внешние фикстуры расширений (P17 — здесь только contract suite);
переименования классов (P15).

## Dependencies

duplicate policy и порядок → freeze → fingerprint → durable-потребители → lifecycle →

## Validation (ожидаемая форма)

Оба лейна плюс `composer test:pg` для durable-полей. Тест duplicate policy: коллизия
идентификатора даёт ошибку компиляции с именами обоих источников. Тест детерминизма: два
прогона компиляции при неизменных входах дают одинаковый порядок и одинаковый fingerprint;
изменение версии модуля меняет fingerprint. Тест заморозки: попытка регистрации после freeze
отклоняется. Тест повторного исполнения: durable-решение, созданное до смены набора
расширений, при повторе использует зафиксированную версию, а не текущую. Contract suite
проходит на модельном внешнем расширении.
