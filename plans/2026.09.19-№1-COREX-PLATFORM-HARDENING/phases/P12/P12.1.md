### P12.1 — Core error vocabulary, policy and zone classification

**Intent:** Introduce `ErrorCategory`, five `UnavailabilityReason` values,
immutable `ErrorDescriptor` and `DescribesError`; make their compatibility and
result-vs-exception rules normative and classify all new core files under P6.

**Why:** `research/P12-design.md` §1, §8; D60. Packages need a shared semantic
shape but must retain exception/result ownership; a shared base hierarchy would turn
core into a catalogue of every package failure.

**Scope Included:** Four additive public primitives and validation; stable vs human fields;
RFC 6901 path; retry meaning; five-reason matrix; result/exception table; API policy update;
P6 zone map/gate update and focused unit tests.

**Scope Excluded:** HTTP mapping/serialization; package exception conversions; operation observer;
central error-code enum; P13 Problem Details/snapshots; renames.

**Inputs:** `research/P12-design.md`; `research/P12-design-rag.md`;
`phases/P6/P6.1.md`; `phases/P6/P6.2.md`; `phases/P1/P1.5.md`.

**Files:** `packages/core/src/Contracts/DescribesError.php`;
`packages/core/src/Data/ErrorDescriptor.php`;
`packages/core/src/Enums/ErrorCategory.php`;
`packages/core/src/Enums/UnavailabilityReason.php`;

**Implementation Rules:** Use exact enum values and validation from §1. Descriptor has no
HTTP status, Throwable or message. `DescribesError` is an interface under Contracts. Codes stay
package-owned; do not create a global code enum. Detail values are bounded JSON-compatible.
Policy states breaking/additive rules and the exact result/exception table. Add exact new paths
to P6 Foundation classification; do not create an Observability/Error zone or widen an allow-list
by prefix.

**Code Guidance:** Constructor failures use `InvalidArgumentException` because they indicate a
programmer-defined invalid contract, not a public business error. Implement a small private JSON
Pointer validator with `~0`/`~1` checking; do not pull a dependency. Named arguments for repeated
strings/bools. Keep all classes framework-neutral and ≤200 lines.

**Validation:** Unit matrix covers every enum, valid root/nested/escaped pointer, invalid code,
invalid escape/control/oversize detail and retry semantics. Root Arch passes. Plant one temporary
unclassified error file: R-Z0 fails by path, then remove it. Policy contains stable-field and
result/exception tables. Core lint/analyse/test and root `composer test:arch` green.

**Deliverables:** Shared descriptor/interface/enums, normative compatibility policy, updated
zone authority and negative gate evidence.
