### P12.3 — Attributes error distinctions and result/exception proof

**Intent:** Split measured attributes failures into capability unavailable,
access denied and schema conflict/retry exhaustion without parsing messages.

**Why:** `research/P12-design.md` §1.4, §3; A94/A97. `ScopeDenied` currently
represents both authority denial and state-machine conflict, while an absent engine
throws a semantically named but unclassified exception.

**Scope Included:** `DescribesError` on unavailable/access failures; new package-local schema
conflict with named constructors; two producer corrections; focused stable-code tests.

**Scope Excluded:** Repository-wide exception rewrite; disabled/entitlement producer without
authority; API serialization; attribute evolution redesign; renames.

**Implementation Rules:** Codes/reasons/retry values are exactly §3. Keep `ScopeDenied` only for
actor/scope/connection authority failures. Named conflict constructors own not-ready, stale and
retry-exhausted text/descriptor; caller never branches on message. No broad catch/translation layer.
Do not emit disabled or entitlement without a real decision source.

**Code Guidance:** Implement descriptors directly on final package exceptions; do not subclass a
CoreX error. Replace only the two inventoried misuse paths. Preserve transaction/idempotency behavior.

**Validation:** Unit tests assert exact code/category/reason/retryability and message independence;
PG tests prove access denial, stale/not-ready conflict and exhausted retry are distinct and preserve
database state. Attributes lint/analyse/test and isolated `test:pg` green after DB preflight.

**Deliverables:** Three machine-distinct package failures and a bounded concrete proof of the
result/exception policy.
