### P12.5 — Bounded metrics, P5 trace carrier and optional OpenTelemetry bridge

**Intent:** Add the executable metric-label allow-list, persist W3C trace context
through P5 metadata, link consumer work and export aggregate delivery health through
an optional pinned OpenTelemetry adapter.

**Why:** `research/P12-design.md` §5–§6; D62–D63; P5 §9.4. Correlation id is
not a trace id, Development conventions cannot silently drift, and per-account or
per-contract labels would create unbounded time series.

**Scope Included:** `MetricAttributes`; vendor-neutral trace bridge + null default; OTel adapter;
`SqlOutbox` injection into existing metadata; consumer link at span creation; aggregate P5 health
instruments; explicit dependency metadata; default composition and tests.

**Scope Excluded:** Mandatory SDK/exporter; collector config; auto-instrumentation; SLO/alerts;
new DDL/envelope field; account/workspace/actor/contract labels; replacing P5 health command.

**Inputs:** `phases/P12/P12.4.md`; `phases/P5/P5.2.md`; `phases/P5/P5.5.md`;
`phases/P5/P5.10.md`; `artifacts/P12-design-rag/P12-Q2-observability.md`.

**Implementation Rules:** Allowed metric keys and retry buckets are exact §5; unknown key throws
before SDK call. IDs never become labels. `SqlOutbox` injects carrier before persistence without
changing message identity/payload/correlation. Consumer uses extracted producer context only as a
link created with the span; never parent-by-correlation and never late link. `linkedConsumer()` owns
the callback boundary: null and failure-fallback paths invoke business work exactly once, preserve its
result/exception and always close any opened scope. Default bindings are null.
Declare both `psr/log` and OTel as suggest + require-dev, never require. Pin tested
Development-semconv schema/version in adapter constant. Export global DeliveryHealth values only;
omit per-contract map.

**Code Guidance:** Keep all SDK names inside `OpenTelemetryBridge`; vendor-neutral interfaces must
load with the package absent. Carrier permits only validated `traceparent`/`tracestate` string keys.
Use SDK in-memory exporter/fakes for tests, no network. Composer-lock changes belong to the item only
if the root qualification workflow requires them.

**Validation:** Forbidden `account_id`, `contract`, arbitrary key and high-cardinality ID all fail;
five allowed keys and four retry buckets pass. Producer metadata round-trips through outbox hydration;
consumer span has one valid link and no fabricated trace id. Aggregate health exports five instruments
with no forbidden dimensions. Test default boot after removing OTel from an isolated install and test
adapter with dev SDK installed. Core lint/analyse/test plus relevant P5 PG health test green.

**Deliverables:** Enforced cardinality boundary, durable trace carrier, optional pinned OTel bridge,
aggregate delivery metrics and no-SDK/default-boot evidence.
