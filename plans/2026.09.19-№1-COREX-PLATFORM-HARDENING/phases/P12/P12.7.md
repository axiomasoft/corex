### P12.7 — Impersonation session invariants and cleanup

**Intent:** Complete the real tenancy session with immutable initiator/target/reason,
no nesting and fail-closed cleanup while retaining existing write guards.

**Why:** `research/P12-design.md` §7.2; D64/A98. Grant validation/TTL/revocation
exist, but nested start is not rejected explicitly, reason is lost after claim, and
failed target login can leave session state populated.

**Scope Included:** Reject nested start before claim; reason in session/state/mirrors/events; session
rotation; failed-login cleanup + failure mirror; legacy missing-reason recovery; expiry/revocation and
write-policy regression.

**Scope Excluded:** New grant DDL; changing approval predicates; allowing new writes; in-flight request
interruption; cross-account support policy redesign; audit enrichment (P12.6).

**Implementation Rules:** Follow exact seven-step start sequence in §7.2. Nested denial occurs
before the atomic UPDATE so the second grant remains unused. Real state reason is non-empty. Legacy
session recovery reads only its already-claimed grant; missing/invalid reason closes session. Failed
login keeps grant consumed, clears auth/session/memo and writes a failure mirror. Expiry/revocation
blocks before `$next`; no claim about killing in-flight work. Do not alter L1/L2/L3 allow semantics.

**Code Guidance:** Centralize session-key list and cleanup so stop/failure use the same forget path.
Use named event parameters and append reason compatibly. Root mirror records initiator, target, grant,
reason and outcome; do not put free-form reason in operational logs/metrics.

**Validation:** Isolated PG cases: nested start denies and second grant unused; successful state/mirrors/
events carry reason; missing-reason legacy state recovers or closes; target-login failure leaves no auth,
session or memo and has one failure mirror; expired/revoked request never reaches handler; initiator/
target cannot change; explicit stop idempotent; all prior write-guard positive/negative tests unchanged.
Tenancy lint/analyse/test and `test:pg` green after DB isolation preflight.

**Deliverables:** Complete impersonation lifecycle invariants, cleanup evidence and unchanged write-policy proof.
