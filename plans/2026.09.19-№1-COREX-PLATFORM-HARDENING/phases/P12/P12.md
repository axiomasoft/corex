# P12 — Таксономия ошибок и наблюдаемость операций

## Phase Context

`RAG:—` API уже имеет safe `ApiError`, `requestId` и envelope, но
не имеет category/path/retryability/correlation. Пакеты владеют
типизированными отказами, но `Unavailable`/`ScopeDenied` местами
смешивают разные действия клиента. Long-operation seam нет.
Имперсонация уже имеет TTL/revocation и три write-guard слоя, но
direct audit callers могут не записать staff/target/reason.

`RAG:✅` Perplexity MCP + official primary-source verification подтвердили:
RFC 9457 не делает human detail machine contract; OTel async causality
требует propagated context + link at span creation; messaging conventions
остаются Development; metric attributes обязаны быть bounded. GCP/AWS
подтверждают dual identity, source identity и expiry/revocation; запрет
nested CoreX sessions остаётся локальным security decision.

> **Контракт фазы.** Потребляет P5 envelope/DeliveryHealth,
> P6 zone gate и итоговую P9 impersonation structure. Производит:
> descriptor-based error vocabulary без base hierarchy; пять различимых
> unavailability reasons; result/exception policy; internal API projection без
> wire change; typed operation lifecycle; PSR-3/optional OTel bridge; executable
> cardinality rule; complete impersonation audit snapshot.

> **Phase Assurance | v1.**
> Impact: public-contract
> Integration Seams: public-error-codes · request-correlation · operation-lifecycle · messaging-trace-context · logs-and-metrics · audit-records · impersonation
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: additive public vocabulary is full-reviewed; adapters are isolated;
> security/audit and final ratchet items are full-reviewed. P12.8 assembles final proof.

## Scope Included

`ErrorCategory`, `UnavailabilityReason`, `ErrorDescriptor`, `DescribesError`; stable-code
compatibility and result-vs-exception article; additive API metadata/correlation with old wire
shape; measured attributes error split; typed start/completed/failed observation; null, PSR-3
and optional OTel adapters; W3C trace carrier in existing P5 metadata and consumer span link;
aggregate P5 health metrics; exact metric dimension allow-list; synchronous impersonation audit
enrichment; nested-session rejection, reason propagation, failed-login cleanup and expiry/
revocation/write-guard regression; root contract ratchets and release/reference records.

## Scope Excluded

External error envelope, `application/problem+json`, error/OpenAPI snapshots and content
negotiation (P13); own tracing backend/exporter/collector; mandatory OTel runtime; SLO/alerts;
account/contract ids as metric labels; central exception base class; repository-wide exception
rewrite; fabricated entitlement source; DDL; in-flight request interruption on revocation;
loosening impersonation guards; renames (P15); acceptance fixtures (P17).
