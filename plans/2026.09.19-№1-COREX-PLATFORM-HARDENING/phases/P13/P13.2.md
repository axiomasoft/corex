### P13.2 — One transport-neutral operation invocation seam

**Intent:** Route HTTP operations and exposed tools through one `OperationInvoker`
without changing standalone tool semantics.

**Why:** `research/P13-design.md` §2; D66. Today two callers independently resolve and
invoke handlers, so authorization/field/idempotency parity cannot be guaranteed.

**Scope Included:** Invocation/result DTOs; invoker interface/default implementation;
exactly-once callback; HTTP delegation; exposed-operation tool delegation; current-context
installation/restoration; parity fixture.

**Scope Excluded:** New authorization implementations; idempotency persistence; field
filtering; HTTP serialization; standalone tool guard rewrite; OperationHandler signature.

**Inputs:** `phases/P13/P13.1.md`; `research/P11-design.md`;
`packages/api/src/Internal/GuardedToolInvoker.php`; `packages/api/src/Dispatcher.php`.

**Implementation Rules:** Invoker accepts no HTTP type/metadata. Module activation and existing
operation authorization remain exactly once. Exposed tools resolve `operationRef` to the same
P13.1 descriptor, retain ToolPolicy/schema/guard before shared invocation and call the handler
once. Standalone tools remain on their current direct path. Always restore RequestContext in
`finally`; callback double-call is an internal failure.

**Code Guidance:** Keep `Dispatcher` as normalization adapter. Extract, do not copy, handler
resolution/context lifetime. `OperationResult` carries semantic data/replayed only; HTTP status
and headers are P13.4. Use named arguments and final readonly DTOs.

**Validation:** Same operation through HTTP and exposed tool sees identical principal/tenant/
input/parameters and increments handler once per call. Denied activation/authorization never
calls handler. Throwing handler restores context. Standalone read/write tool regression remains
green. API lint/analyse/test green.

**Deliverables:** Shared invocation seam, two projections wired to it, parity and regression proof.
