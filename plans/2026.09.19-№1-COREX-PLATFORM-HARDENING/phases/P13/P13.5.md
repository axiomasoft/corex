### P13.5 — Tenant idempotency store and schema

**Intent:** Add the durable tenant-local store and lifecycle primitives required to admit
mutation execution safely under one key.

**Why:** `research/P13-design.md` §5.2; D104 supersedes D69 for effect/outcome atomicity.
Memory/cache state cannot preserve replay
across workers or align naturally with physical DB-per-account isolation.

**Scope Included:** Store contract and attempt/scope DTOs; tenant migration; SQL begin/
complete/fail/takeover/prune; HMAC key digest; contract-hash binding; table ownership;
SQLite behavioral and PostgreSQL concurrency tests.

**Scope Excluded:** HTTP header parsing; invocation decorator; cross-account central index;
direct external/other-connection effects without same-transaction outbox intent or explicit
reconciliation contract; permanent deduplication.

**Implementation Rules:** Exact columns/unique key/state transitions from §5.2. Success outcome and handler mutation share one active-tenant connection and transaction; external effects use outbox. Store only key
HMAC, never raw key. Every update predicates on lease token/state/fingerprint; a stale owner cannot
overwrite a takeover. Terminal outcome and contract hash are canonical bytes. Prune terminal expired
only. Migration is published under explicit tenant tag, never auto-run or central.

**Code Guidance:** Follow P5 lease/fence and P4 clock patterns; use injected `ClockInterface` after
P4/P12 dependency results. PostgreSQL unique/lease test uses two connections after isolation preflight.
SQLite test proves state machine but is not concurrency evidence. An ambiguous commit outcome maps
to `reconciliation_required`; lease expiry alone never admits a blind second effect. No new dependency.

**Validation:** G-DDL evidence resolves before write. A crash after mutation but before terminal persistence rolls back both and retry commits exactly once. Fresh/same/different/live/stale/terminal/expired
matrix; two concurrent begin calls yield one owner; stale lease takeover fences prior token; wrong
active tenant connection fails; prune retains live rows. Rollback drops only new table. API lint/analyse/
test and isolated `test:pg` green; migration ownership recorded.

**Deliverables:** Tenant migration, durable store contract/implementation, concurrency/retention
evidence and table-ownership record.
