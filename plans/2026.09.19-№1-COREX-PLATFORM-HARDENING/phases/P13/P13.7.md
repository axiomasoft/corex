### P13.7 — Signed scoped cursor and ordering registry

**Intent:** Provide `api-cursor/1` with opaque authenticated continuation, explicit ordering
version and typed page helpers.

**Why:** `research/P13-design.md` §6; D70. Offset pagination and unsigned/base64 state cannot
protect tenant/filter/order semantics under concurrent data.

**Scope Included:** Keyring contract; payload/position/page types; signed codec; immutable ordering
registry from operation descriptors; filter/scope fingerprint; TTL/key rotation; tuple vectors.

**Scope Excluded:** Generic SQL/repository builder; snapshot isolation; search cursor migration;
provider-specific page tokens; P14 bulk pagination.

**Inputs:** `phases/P13/P13.1.md`; `phases/P13/P13.3.md`; `phases/P4/P4.7.md`;
`packages/search/src/Internal/Query/SearchCursorCodec.php`.

**Implementation Rules:** Exact wire/payload/check order from §6. Payload contains values only;
registry owns fields/direction/type arity and last key is unique tie-breaker. Scope binds trusted
account/workspace/version/operation plus canonical filters/selection. Constant-time HMAC, bounded
decoded size/depth and generic invalid error. Verifying keys outlive max TTL; unknown ordering is
distinct from malformed cursor.

**Code Guidance:** Use `JsonCanonical`; base64url helpers stay private. Inject Clock/keyring, never
call config/env in codec. `CursorPage` accepts raw next values and encodes only after output assembly.
Do not import search package or change its `v1` bytes.

**Validation:** Golden encode/decode; tamper at each segment; unknown/expired key; expired cursor;
wrong tenant/workspace/filter/fields/version/operation/direction/order/arity/type; equal primary sort
values continue by unique tie-breaker without repeating boundary. Reverse registry order deterministic.
API lint/analyse/test green.

**Deliverables:** `api-cursor/1` codec/types/ordering registry, key-rotation rules and negative vectors.
