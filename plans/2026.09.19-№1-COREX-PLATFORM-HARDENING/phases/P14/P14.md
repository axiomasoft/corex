# P14 — Нагрузочный контур API: бюджеты стоимости, bulk-операции, webhooks

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается `design-phase: task:plan-design 2026.09.19-№1-COREX-PLATFORM-HARDENING P14`

RAG:— Три отсутствующих слоя, без которых коммерческая эксплуатация упирается в первый же
крупный клиент: (1) все операции стоят одинаково, поэтому глубокий фильтр по атрибутам и
выборка одной записи расходуют один и тот же лимит; (2) больших выгрузок и загрузок нет как
контракта — есть только движок переноса внутри `corex/transfer`, у которого при этом нет отмены,
а объявленные лимиты памяти и времени внутри исполнителя не применяются; (3) webhook-поверхности
не существует вообще — в дереве только два комментария со словом «webhooks».

RAG:✅ Cost-модель: Shopify считает лимит по стоимости выбранных полей, использует leaky bucket
и возвращает запрошенную и фактическую стоимость, изолируя бюджет по паре «приложение + магазин».
RAG:✅ Bulk/LRO: четыре независимые платформы дают один набор — id операции, опрос статуса,
типизированный результат, ошибка исполнения отдельно от ошибки старта, отмена best effort, срок
жизни результата, record-level ошибки. RAG:✅ Webhooks: Standard Webhooks задаёт `webhook-id`,
`webhook-timestamp`, `webhook-signature`, подпись над `{id}.{timestamp}.{raw_body}`, окно
проверки времени, `webhook-id` как ключ идемпотентности, список подписей для ротации секретов
без простоя, успех только 2xx, backoff с jitter, историю доставок и ручной replay.

Важное ограничение: для self-hosted установки SaaS-лимиты неуместны — это прямо сказано в
разделе аудита «что не копировать». Поэтому cost-модель принимается как opt-in политика (Q4).

> **Контракт фазы (contract-first).** Потребляет: `operation-contract/1` P13, outbox P5,
> наблюдателя операций P12. Производит: оценщик и бюджет стоимости с иерархией лимитов и
> возвратом неиспользованной части, bulk/long-running контракт поверх `corex/transfer` (D9),
> отмену и enforcement лимитов в исполнителе переноса, webhook-подписки и доставку по
> Standard Webhooks с историей и replay. Границы: GraphQL не поддерживается (D7); движок
> исполнения переноса не дублируется.

## Scope Included

Оценщик стоимости операции по объявленному весу и параметрам вызова (размер страницы,
запрошенные поля, вложенные связи, фильтры по атрибутам, подсветка поиска, размер выгрузки,
синхронные побочные эффекты), без запроса к базе ради оценки. Бюджет с резервированием,
расчётом фактической стоимости и возвратом неиспользованной части; отдача состояния лимита
в метаданных ответа. Иерархия лимитов: глобальный предохранитель → аккаунт → клиентское
приложение → актор; идентификатор операции не входит в ключ хранилища. Режим по умолчанию —
наблюдение с отказом только на глобальном предохранителе (решение Q4). Bulk/long-running
контракт: приём, опрос статуса, типизированный результат, отмена, срок жизни, record-level
ошибки; состояния операции; store операций. Делегирование исполнения в `corex/transfer`
(D9) и достройка `corex/transfer` до кооперативной отмены и фактического применения объявленных
лимитов памяти, времени и размера батча. Webhook: подписки, фиксирующие мажор API; топики как
версионированные интеграционные события; доставка из outbox; подпись над точными байтами тела
с идентификатором доставки и временем; окно проверки времени; несколько активных секретов и
ротация без простоя; трактовка кодов ответа; backoff с jitter и предел попыток; dead-letter;
история попыток с редакцией секретов; явный replay одной доставки и диапазона; ограничение
размера payload; SSRF-защита исходящих запросов; PII-классификация топиков.

## Scope Excluded

GraphQL и стоимость по selection set GraphQL: оценщик принимает набор запрошенных полей и
вложенность как входные данные, поэтому пригоден для другого транспорта без смены контракта —
это и есть весь задел по D7, отдельной работы под GraphQL фаза не содержит;
дублирование движка переноса; биллинг и тарификация; обязательные SaaS-лимиты в self-hosted
поставке; внешние брокеры сообщений; переименования (P15).

## Validation (ожидаемая форма)

Оба лейна плюс обязательный `composer test:pg`. Contract-тесты: запрос, превышающий бюджет,
отклоняется; неиспользованная запрошенная стоимость возвращается; бюджеты аккаунтов
изолированы; прерванная bulk-операция возобновляется; отмена останавливает исполнение не
позднее объявленной границы; лимиты памяти и времени фактически применяются. Webhook: подпись
проверяется над точными байтами; повторная доставка не даёт второго бизнес-эффекта; обе
подписи принимаются в окне ротации; при исчерпании попыток доставка уходит в dead-letter с
сохранённой историей; SSRF-политика отклоняет приватные и metadata-адреса. Все доставки в
тестах — только на локальный приёмник; обращений к внешним хостам нет.
