# P15 — Раскатка словаря имён по реестру переименований

## Phase Context

P15 применяет реестр P1 после семантических фаз P6, P9, P10 и P13. Это чистая 1.0
breaking-граница по D85: aliases, forwarding classes и автоматический Composer `replace` не
добавляются. Поведение, persisted identifiers, config keys и artisan signatures сохраняются,
если отдельное принятое решение явно не говорит обратного.

Класс модуля и module id разведены D86: `CorexModule` → `ModuleDefinition` меняет PHP FQCN,
но не composer-name в `extra.corex.module` и не требует DDL/backfill `mod_*`. Полный wakeup
словарь задан D87. Core-zone FQCN moves приняты D88 и выполняются здесь, а не в структурной P16.
Q1/Q2 остаются owner gates только для conditional items P15.11/P15.12 (D89/D90 proposed);
остальная фаза от них не блокируется.

> **Контракт фазы (contract-first).** Потребляет: materialized P1 rename registry; терминальные
> P6/P9/P10/P13 и их receipts; принятые D85–D88; owner evidence для conditional package items.
> Производит: namespace-coherent rename set, обновлённые metadata/docs/root CHANGELOG и
> машинно проверенный zero-old-name receipt. Не производит: совместимые aliases, DB migrations,
> новое поведение или структурный profile rollout P16.

> **Phase Assurance | v1.**
> Impact: public-contract
> Integration Seams: public-symbols-all-packages · composer-autoload · module-discovery · artisan-signatures · split-package-identities · persisted-identifiers
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: массовый rename публичных FQCN и два условных package-identity rename требуют
> полного API-аудита и отрицательной проверки полноты.

## Scope Included

- Modules: `Dep`, его поля, `Manifest`, `GateDecision`, `SettingDefault`,
  `ModuleContext`, `CorexModule`, `WhyCommand` и девять module consumers.
- Attributes, Search, Meilisearch, Transfer, Tasks Workflow, Wakeup, API и Tenancy mappings из
  `research/P15-design.md` §2.
- Core-zone public FQCN moves из D88.
- Conditional package identity/directory/split rename для API/Auth строго по D89/D90 owner
  outcome.
- Public API manifests, autoload metadata, architecture allowlists, PHPStan, docs/examples и
  только корневой `CHANGELOG.md`.
- Final planted-old-name negative gate и phase receipt.

## Scope Excluded

Поведенческие изменения; config/route/artisan signature rename; persisted module-id migration;
`class_alias`; compatibility wrapper; новые runtime dependencies; `Extend`/`Gate`;
`RecordRules`; package `wakeup` rename; profile/directory regrouping P16, кроме двух явно
owner-gated package identity renames; per-package changelogs.

## Dependencies

Execution: P1.7, P2.6, P3.7, P6.6, P9.8, P10.8, P13.12 терминальны и Stage 2 whole-plan
audit пройден. P15.13 ждёт terminal/skipped P15.1–P15.12; P15.14 ждёт P15.13. Между
P15.2–P15.6 допускается параллельность. Conditional P15.11/P15.12 не блокируют прочие items:
при owner reject они закрываются `skipped` с evidence.

## Validation

Каждый rename lane проходит package lint/analyse/test и `composer dump-autoload --strict-psr`.
Финал проходит root architecture/package graph/public API/naming gates и `composer
test:packages`. Для каждого old name машинный sweep пуст вне разрешённых historical/design
carriers. Negative fixture со старым именем обязана уронить completeness gate и после удаления
вернуть green. Module discovery доказывает все девять module entries; artisan
`corex:modules:why` и persisted composer module ids неизменны. Skipped check не считается green.
