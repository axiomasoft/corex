# P15 — Раскатка словаря имён по реестру переименований

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается `design-phase: task:plan-design 2026.09.19-№1-COREX-PLATFORM-HARDENING P15`

RAG:— Фаза выполняет уже утверждённый в P1 реестр переименований и ничего не решает заново.
Она идёт после того, как семантика зафиксирована шестью фазами: ядро сокращено, tenancy
разложен по контекстам, источник определений атрибутов стал сменным, внешний API получил
словарь операций. Это прямое требование аудита: физические перемещения и переименования не
должны предшествовать семантическим решениям.

Часть предложенных аудитом переименований отклонена и в реестр не попадает: `Extend`→`Extension`
и `Gate`→`Activation` (доктринально закреплённые имена закрытого набора extenders),
`RecordRules`→`RecordAccessPolicy` (класса не существует). Часть принята с изменением: класс
`WhyCommand` переименовывается, а сигнатура artisan `corex:modules:why` сохраняется; module id
остаётся composer-именем и не меняется вместе с классом модуля.

До 1.0 действует чистое переименование без deprecated-алиасов (доктрина допускает breaking в
minor до 1.0 с объявлением в CHANGELOG) — алиас вводится только там, где уже существует
внешний потребитель.

> **Контракт фазы (contract-first).** Потребляет: `naming.md` и реестр переименований P1,
> гейт словаря P3, закрытые Q1/Q2. Производит: применённые переименования классов и полей,
> обновлённые публичные поверхности и CHANGELOG'и, при необходимости — миграцию `mod_*` для
> класса модуля. Границы: поведение не меняется; ни один публичный символ не исчезает без
> записи в CHANGELOG затронутого пакета.

> **Phase Assurance | v1.**
> Impact: public-contract
> Integration Seams: публичные символы всех пакетов; FlexCRM как потребитель; `mod_*` как
> хранилище идентификаторов модулей; сигнатуры artisan-команд
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: Механическая работа под уже утверждённым реестром, поэтому Review — `light`;
> item переименования класса модуля с миграцией `mod_*` — `full`.

## DoR (Definition of Ready)

- [ ] Каждое переименование в реестре имеет: текущее имя, целевое, радиус (число файлов),

- [ ] Каждая item-спека называет параграф `research/P15-design.md` с готовой таблицей замен.
- [ ] Ни один item не превышает бюджет 200K.

## Scope Included

Переименования `packages/modules`: `Dep`→`ModuleDependency` с полями `$kind`/`$package`,
`Manifest`→`ModuleManifest`, `GateDecision`→`ModuleActivationDecision`,
`SettingDefault`→`DefaultSettingDefinition`, `ModuleContext`→`ModuleRuntimeContext`,
`CorexModule`→`ModuleDefinition` (с миграцией всех наследников в монорепо),
класс `WhyCommand`→`ExplainModuleCommand` при сохранении сигнатуры команды.
Сквозные переименования: `RegistryFieldCatalogue`→`ModuleFieldCatalogue`,
`StructuralAttributeFilter`→`SchemaAttributeFilter`, `WriteResult`→`AttributeWriteResult`,
`OperationKey`→`SchemaOperationId`, `UnsupportedSearchProvider`→`UnavailableSearchProvider`,
`MeilisearchQueryAdapter`→`MeilisearchSearchProvider`,
`DatabaseTransferRunner`→`SqlTransferExecutor`, `ImportTarget`→`TransferSink`,
`AccountsResult`→`AvailableAccounts`, `CompletionCaptureObserver`→`CaptureTaskCompletion`,
`TasksWorkflowModule`→`TaskWorkflowIntegration`, контракты wakeup
(`DueSource`→`DueWakeupSource`, `WakeupHandler`→`DueWakeupHandler`,
`WakeupSweeper`→`DueWakeupSweeper`, `WakeupHint`→ уточнённое имя по семантике), классы
внешнего API (`Dispatcher`→`OperationDispatcher`, `ErrorBoundary`→`OperationErrorBoundary`,
`RequestMetadata`→`InvocationMetadata`, `OpenApi`→`OpenApiDocumentGenerator`).
Переименования пакетов — только при закрытых Q1/Q2. Обновление `extra.corex.public-api`,
allowlist'ов гейта графа, PHPStan-конфигов, README и примеров.

## Scope Excluded

Смена module id (остаётся composer-именем по D82); изменение сигнатур artisan-команд и ключей
конфигурации; переименование `Extend`, `Gate` и имени пакета `wakeup`; введение
deprecated-алиасов там, где внешнего потребителя нет; изменение поведения; перемещение
каталогов (P16).

## Dependencies

P6, P9, P10, P13 терминальны. Q1/Q2 закрыты для items переименования пакетов. Внутри фазы:
modules → attributes → search → transfer → tasks-workflow → wakeup → api → пакеты (если разрешено).

## Validation (ожидаемая форма)

Оба лейна по каждому затронутому пакету плюс `composer test:packages`. Полнота каждого
переименования доказывается пустым выводом repo-wide sweep по старому имени (исключая
CHANGELOG-записи о ренейме). Гейт словаря имён зелёный. `composer package-graph-gate` и
`composer test:arch` зелёные. Для P15.2 — наблюдаемое доказательство, что discovery модулей
по-прежнему проходит для всех девяти пакетов с `extra.corex.module`.
