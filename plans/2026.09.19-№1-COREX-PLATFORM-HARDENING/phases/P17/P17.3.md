### P17.3 — External REST and MCP consumers

**Intent:** Exercise the frozen operation contract through independent REST and MCP clients and prove schema/error/result parity.

**Why:** `research/P17-design.md` §4. P13 transport tests run inside the package; external clients must consume only published protocol bytes and schemas.

**Scope Included:** Discovery/schema loading; query/command/idempotency/cursor/error flows; MCP tool invocation; REST/MCP parity; stale/tampered schema negatives.

**Scope Excluded:** CoreX PHP imports; generated SDK; GraphQL; new endpoint/tool; bulk/webhooks; Internet egress.

**Inputs:** `phases/P17/P17.1.md`; `phases/P13/P13.10.md`; `phases/P13/P13.12.md`; `phases/P14/P14.18.md`; `decisions/D105-replay-rechecks-current-authorization.md`; `decisions/D106-resource-id-covers-all-id-strategies.md`.

**Files:** `fixtures/clients/rest/**`; `fixtures/clients/mcp/**`; `scripts/distribution/verify_api_clients.py`; `scripts/distribution/tests/test_api_clients.py`; `.github/workflows/distribution-proof.yml`; `plans/2026.09.19-№1-COREX-PLATFORM-HARDENING/findings/P17-api-client-receipt.json`.

**Required Reads:** 1) `phases/P17/P17.md`; 2) `research/P17-design.md` §0, §4; 3) `phases/P17/P17.1.md`; 4) `phases/P13/P13.12.md`; 5) `research/P13-design.md` §2, §5, §9; 6) `decisions/D66-one-operation-invoker.md`; 7) `decisions/D72-error-descriptor-has-two-http-representations.md`; 8) `phases/P13/P13.10.md`; 9) `decisions/D105-replay-rechecks-current-authorization.md`; 10) `decisions/D106-resource-id-covers-all-id-strategies.md`.

**Implementation Rules:** Follow §4 exactly. Clients read committed snapshots before calls, treat cursor as opaque, use one idempotency key for the replay pair and compare semantic results/errors. No source/autoload access and no assumptions outside published protocol.

**Code Guidance:** Use stdlib clients and a local test server. Normalize only fields declared non-semantic by the snapshot; do not mask status/code/body differences. Tamper a copied snapshot, never the canonical file.

**Validation:** Query, command, idempotent replay, cursor continuation and both error media types pass via REST; matching exposed operation passes via MCP; parity receipt binds snapshot digests. HTTP success→record/field revocation→MCP replay denies/prunes with one effect. UUIDv7, UUID, ULID and integer ResourceIds round-trip through both clients. Stale digest, unexpected field and GraphQL artifact fail.

**Deliverables:** Two external client fixtures and digest-bound REST/MCP parity evidence.
