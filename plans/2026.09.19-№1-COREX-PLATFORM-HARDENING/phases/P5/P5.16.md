### P5.16 — Align configurable messaging table names with DDL

**Authority:** routine

**Intent:** Make messaging migrations and runtime use the same configured outbox/inbox table names.

**Why:** EA04 proves a non-default configuration migrates default tables while runtime queries
custom names, producing a deterministic production failure.

**Scope Included:** two new P5 migrations; safe identifier handling for their raw indexes; PG
custom-name witness; CHANGELOG and receipt.

**Scope Excluded:** changing columns or indexes semantically; existing frozen tables; renaming
default tables; down migrations; unrelated Config accessors; applying DDL to any non-test database.

**Inputs:** `research/P4-P5-execution-remediation.md` §5; `findings/execution-audit-P1-P5-2026-09-22.md` EA04; `phases/P5/P5.4.state.md` (producer: P5.4); `decisions/D27-outbox-in-tenant-database.md`; `decisions/D110-g-ddl-grant-p54-messaging-tables.md`; `decisions/D115-p516-local-source-owner-direction.md`.

**Required Reads:** 1) `phases/P5/P5.md`; 2) `research/P4-P5-execution-remediation.md` §5; 3) `findings/execution-audit-P1-P5-2026-09-22.md` EA04; 4) `phases/P5/P5.4.state.md`; 5) `decisions/D27-outbox-in-tenant-database.md`; 6) `decisions/D110-g-ddl-grant-p54-messaging-tables.md`; 7) `packages/core/database/migrations/pg/2026_09_20_100000_create_sys_outbox_messages_table.php`; 8) `packages/core/database/migrations/pg/2026_09_20_100001_create_sys_inbox_messages_table.php`; 9) `packages/core/src/Support/Config.php`; 10) `packages/core/database/migrations/pg/2026_07_13_100000_create_sys_settings_table.php` (configurable migration precedent); 11) `packages/core/tests/Pg/MessagingSchemaTest.php`.

**Implementation Rules:** D115 limits execution to local source changes and isolated `corex_test`.
Use the two Config accessors for Schema creation and every raw index target. Validate/wrap
identifiers through framework-safe mechanisms; no unchecked SQL concatenation. Defaults and schema
shape remain byte-equivalent in effect. Test overrides are restored in `finally`.

**Code Guidance:** Follow §5 and existing `Config::*Table()` migration precedents. The custom-name
witness must prove both positive custom tables/indexes and negative absence of default tables.

**Validation:** isolated `_test` PostgreSQL preflight; focused `MessagingSchemaTest`; full core
`test:pg`, test, analyse and lint; table-ownership gate; `git diff` contains no unrelated migration.

**Deliverables:** configuration-consistent DDL; safe index SQL; custom-name regression witness;
CHANGELOG and receipt with D115 owner-direction evidence.
