### P5.7 — Порт `MessagePublisher` и команда relay с кооперативной остановкой

**Intent:** Ввести контракт `CoreX\Messaging\Contracts\MessagePublisher` с
durable-ack semantics, явную host binding validation, команду
`corex:messaging:relay` с остановкой по `SIGTERM`/`SIGINT` и регистрацию обоих.

**Why:** N05: без запускаемого relay цепочка «изменение домена → событие → потребитель»
остаётся незамкнутой. `RAG:✅` P5-Q5: форма кооперативной остановки — `pcntl_async_signals(true)`,
обработчик сигнала только выставляет флаг, проверка флага **между** сообщениями, выход по
безопасной границе; непрерываемое блокирующее ожидание запрещено; сигнал не доказывает,
что публикация не дошла. `RAG:—` В дереве уже есть единственный канал межпроцессных
уведомлений ядра — `CoreX\Contracts\PubSub` с тремя драйверами и запретом `LISTEN`/`NOTIFY`
(R-15); второй транспорт вводить нельзя. Порт нужен, чтобы P14 подставила webhook-доставку,
а P10 — поисковую проекцию, не переписывая relay (§6.1).

**Scope Included:** контракт порта, где success = durable broker/store
acceptance; команда по §6.2; регистрация команды в `CoreServiceProvider::boot()`;
проверка host binding без lossy default; тесты durable/unbound/lossy и команды;
строка в `CHANGELOG.md`;
receipt.

**Scope Excluded:** webhook-доставка, подписи и ротация секретов (P14); поисковая проекция
(P10); второй транспорт помимо существующего `PubSub`; изменение любого файла
`packages/core/src/PubSub/**` (D31, перенос — P6); планировщик по многим аккаунтам (P9,
D27); механика захвата и отметки — она в P5.6; изменение `config/corex.php` и
`Support/Config.php` (P5.4).

**Inputs:** результат P5.3 (реестр контрактов — источник канала), P5.6 (`OutboxRelay`,
`LeasedMessage`, `OutboxLeaseLost`); `research/P5-design.md` §0, §6;
`research/P5-design-rag.md` §1 (P5-Q5); `findings/audit-verdicts.md` A91, N05; решения
D24, D25, D31, D99.

**Files:** `packages/core/src/Messaging/Contracts/MessagePublisher.php`; `packages/core/src/Messaging/Commands/RelayOutbox.php`; `packages/core/src/CoreServiceProvider.php`; `packages/core/tests/Feature/MessagePublisherTest.php`; `packages/core/tests/Pg/OutboxRelayCommandTest.php`; `CHANGELOG.md`; `plans/2026.09.19-№1-COREX-PLATFORM-HARDENING/findings/P5-receipts.md`

**Required Reads:** 1) `phases/P5/P5.md`; 2) `research/P5-design.md` §0, §5.1, §6; 3) `research/P5-design-rag.md` §1 (P5-Q5); 4) `decisions/D25-outbox-not-aftercommit.md`; 5) `decisions/D31-messaging-zone-logical-not-moved.md`; 6) `packages/core/src/Contracts/PubSub.php`; 7) `packages/core/src/Messaging/Contracts/OutboxRelay.php` (результат P5.6); 8) `packages/core/src/Messaging/Data/MessageEnvelope.php`; 9) `packages/wakeup/src/Commands/SweepWakeups.php` (образец команды пакета: валидация опции, работа на текущем контексте, формат вывода); 10) `packages/core/src/PubSub/PrunePubSubMessages.php` (образец докблока команды с указанием на планировщик); 11) `packages/core/src/CoreServiceProvider.php`; 12) `decisions/D99-durable-outbox-ack-and-bounded-reclaim.md`.

**Implementation Rules:** Код §6.2 с коррекцией D99. Core не связывает
`PubSub`/null/Redis PUBLISH с `MessagePublisher`; отсутствующая или не-durable
реализация отказывает до lease/markPublished. Три требования §6.2 обязаны быть
прочитаны до правки: арендованное, но не опубликованное при остановке сообщение **не**
освобождается явно — его подберёт следующий проход по истёкшей аренде, и явный «возврат
при остановке» ввёл бы четвёртый путь смены статуса; `OutboxLeaseLost` **не** считается
отказом публикации и не ведёт к `releaseWithBackoff()`; `sleep()` вызывается только между
пустыми проходами и только в цикле. Обработчик сигнала выставляет **только** флаг — ни
одного обращения к БД, логу или выводу внутри него. Канал публикации берётся из объявления
контракта, а не из конверта: назначение — свойство контракта. Порядок ключей публикуемого
массива фиксирован и объявлен частью контракта в докблоке — по нему потребитель может
считать отпечаток, поэтому перестановка ключей это ломающее изменение, а не форматирование
(та же причина, что в `ArrayDataScopeCodec` P4.8). Команда регистрируется в
`boot()` внутри `runningInConsole()`, рядом с существующими `PruneAuditLog` и
`PrunePubSubMessages`. Привязка порта — `scoped`. Ни один файл вне `packages/core` не
трогается; каталог `packages/core/src/PubSub/` не изменяется вовсе.

**Code Guidance:** Готовые контракт, реализация и команда — `research/P5-design.md` §6.1–§6.2.
Обоснование отдельного порта («шов, названный заранее, а не прорубленный потом») — §6.1,
первые два абзаца. Состав тестов — §6.3: четыре случая публикатора в sqlite-лейне, три
случая команды в pg-лейне. Тест §6.3(7) требует публикатора-фикстуры, бросающего
`OutboxLeaseLost`; его форма — тот же `RecordingPublisher`, который окончательно
оформляется в P5.12, здесь достаточно локального анонимного класса в тесте.

**Validation:** `composer test` пакета `core` зелёный: durable fixture admits,
unbound/null/Redis-PUBLISH fixtures fail before `markPublished()`. `composer test:pg` пакета `core`
зелёный, три случая §6.3(5–7) покрыты. `composer analyse` зелёный. `composer lint:check`
зелёный. `git diff --stat -- 'packages/core/src/PubSub/'` пуст — подтверждение D31.
`php artisan corex:messaging:relay --once` в тестовом окружении завершается кодом 0.
Receipt содержит вывод всех команд.

**Deliverables:** durable-ack порт публикации без lossy default; host binding
validation; команда relay с кооперативной
остановкой; регистрация и привязка; семь тестовых случаев; строка `CHANGELOG.md`; блок
receipt'а, подтверждающий неизменность каталога `PubSub/`.
