Then, you run Infection for mutation testing, which in its turn, generates Code Coverage again for internal needs. This dramatically increases the build time because running your tests with debugger <em>twice</em> requires too much time.</p><p>With this option it’s possible to reuse already generated coverage in Infection.</p><p>For <code>PHPUnit</code> and <code>Codeception</code>:</p><ul><li>Infection requires both the<code>xml</code> and <code>junit</code> reports to work</li><li>If <code>build/coverage</code> path is provided, it should contain <code>coverage-xml</code> folder and <code>junit.xml</code> file <ul><li><code>build/coverage/coverage-xml/*</code></li><li><code>build/coverage/junit.xml</code></li></ul></li></ul><p>For <code>PhpSpec</code>:</p><ul><li>Infection requires the <code>xml</code> report to work</li><li>If <code>build/coverage</code> path is provided, it should contain <code>phpspec-coverage-xml</code> folder</li></ul><p>Example:</p><div class="language-shell vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">shell</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-dark:#6A737D;"># collect coverage</span></span>

<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-dark:#6A737D;"># use coverage</span></span>
<span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection.phar</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --coverage=build/coverage</span></span></code></pre></div><h3 id="git-diff-filter" tabindex="-1"><code>--git-diff-filter</code> <a class="header-anchor" href="#git-diff-filter" aria-label="Permalink to &quot;`--git-diff-filter`&quot;">​</a></h3><p>Allows filtering files to mutate by using <code>git diff</code> with <code>--diff-filter</code> option. Sensible values are: <code>AM</code> - added and modified files. <code>A</code> - only added files.</p><p>Best to be used during pull request builds on CI, e.g. with GitHub Actions, Travis CI and so on.</p><p>Usage:</p><div class="language-shell vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">shell</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-dark:#6A737D;"># this is needed on GitHub Actions to fetch the base branch to make a diff</span></span>
<span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">git</span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;"> fetch</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --depth=1</span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;"> origin</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;"> $GITHUB_BASE_REF</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection.phar</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --git-diff-filter=A</span></span></code></pre></div><p>This command will mutate only those files that were added in the Pull Request. The diff is done between the current branch and a common ancestor of it and the base branch. If there is no common ancestor available, perhaps because your CI server used a shallow checkout, or you have unrelated branches, infection will use a direct diff between branches as a fallback.</p><blockquote><p>It’s possible to configure the base branch, see <a href="/guide/command-line-options.html#git-diff-base"><code>--git-diff-base</code></a> option</p></blockquote><blockquote><p>It’s possible to mutate only touched <strong>lines</strong>, see <a href="/guide/command-line-options.html#git-diff-lines"><code>--git-diff-lines</code></a> option</p></blockquote><p class="tip">You can check the result of the filter applied by using <code>infection config:list-sources</code> and/or debug the<br> git values used by using the infection git commands. They can be listed with <code>infection list git</code>.</p><br><h3 id="git-diff-base" tabindex="-1"><code>--git-diff-base</code> <a class="header-anchor" href="#git-diff-base" aria-label="Permalink to &quot;`--git-diff-base`&quot;">​</a></h3><p>Supposed to be used only with <a href="/guide/command-line-options.html#git-diff-filter"><code>--git-diff-filter</code></a> option. <span class="line"></span>
<span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection.phar</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --git-diff-base=origin/</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">$GITHUB_BASE_REF</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --git-diff-filter=AM</span></span></code></pre></div><p class="tip">You can check the result of the filter applied by using <code>infection config:list-sources</code> and/or debug the<br> git values used by using the infection git commands. They can be listed with <code>infection list git</code>.</p><br><h3 id="git-diff-lines" tabindex="-1"><code>--git-diff-lines</code> <a class="header-anchor" href="#git-diff-lines" aria-label="Permalink to &quot;`--git-diff-lines`&quot;">​</a></h3><p>Allows mutating only touched <strong>lines</strong> of code. Under the hood, this option mutates only added and changed files, comparing your current branch with <code>master</code> branch by default.</p><p>Base branch can be changed by using <code>--git-diff-base=main</code> option. In this case, your current branch will be compared with <code>main</code> branch.</p><p>Useful to check how your changes impacts MSI in a feature branch. Useful for those who do not want / can’t write tests for the whole touched legacy file, but wants to cover their own changes (only modified lines).</p><p>Can significantly improve performance since fewer Mutants are generated in comparison to using <code>--git-diff-filter=AM</code> or mutating all files.</p><p class="tip">You can check the result of the filter applied by using <code>infection config:list-sources</code> and/or debug the<br> git values used by using the infection git commands. They can be listed with <code>infection list git</code>.</p><br><h3 id="map-source-class-to-test" tabindex="-1"><code>--map-source-class-to-test</code> <a class="header-anchor" href="#map-source-class-to-test" aria-label="Permalink to &quot;`--map-source-class-to-test`&quot;">​</a></h3><blockquote><p>Meant to be used together with <code>--git-diff-lines</code> / <code>--git-diff-filter</code> / <code>--filter</code></p></blockquote><p>This option can dramatically decrease the time needed for “Initial Tests Run” stage.</p><p>If project has <code>N</code> tests files and we run Infection with, for example, <code>infection --git-diff-lines</code> and only 1 file <code>Foo.php</code> is updated/added in a Pull Request - it doesn’t make sense to run all the <code>N</code> tests to generate code coverage if we know that only 1 file of <code>N</code> covers the source code file - <code>FooTest.php</code>.</p><p>In practice, <code>PHPUnit</code> even has different methods that help define which test file covers which class:</p><ul><li><a href="https://docs.phpunit.de/en/11.0/configuration.html#the-requirecoveragemetadata-attribute" target="_blank" rel="noreferrer"><code>requireCoverageMetadata</code></a> configuration attribute</li><li><a href="https://docs.phpunit.de/en/11.0/attributes.html#code-coverage" target="_blank" rel="noreferrer"><code>#[CoversClass(...)]</code></a> attribute</li></ul><p>In the example above, Infection would run only <code>FooTest.php</code> to generate coverage for <code>Foo.php</code>.</p><p>Without this option, Infection will attempt to run <em>all</em> the project’s tests, as it doesn’t know which tests cover <code>Foo.php</code>.</p><p>Currently, <code>--map-source-class-to-test</code> supports the only one strategy of mapping source class to test file: by adding <code>*Test</code> postfix to a file name. If source class is named <code>Foo</code>, Infection will try to run <code>FooTest</code>.</p><p>Under the hood, it builds a regex for <code>--filter</code> option: <code>--filter=&#39;FooTest|BarTest&#39;</code>.</p><h3 id="id" tabindex="-1"><code>--id</code> <a class="header-anchor" href="#id" aria-label="Permalink to &quot;`--id`&quot;">​</a></h3><p><span class="version-since">Available in Infection 0.30.0+</span></p><p>Run only one Mutant by its ID. <span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --static-analysis-tool=mago</span></span></code></pre></div><p>When enabled, Infection will:</p><ol><li>Run an initial static analysis check to ensure the tool passes and warm up caches</li><li>Execute the static analysis tool for each mutant that escapes (is not killed by) the test suite</li><li>Mark escaped mutants as “Killed by SA” if the static analysis tool detects errors</li></ol><p>This feature helps improve mutation testing effectiveness by catching logical errors that tests might miss, such as:</p><ul><li>Type violations</li><li>Dead code detection</li><li>Unreachable code paths</li></ul><p><strong>Requirements for PHPStan:</strong></p><ul><li>PHPStan must be installed at <code>vendor/bin/phpstan</code></li><li>A valid PHPStan configuration file should be present in your project</li></ul><p><strong>Requirements for Mago:</strong></p><ul><li>Mago (&gt;= 1.23.0) must be installed at <code>vendor/bin/mago</code></li><li>Install via Composer: <code>composer require --dev carthage-software/mago</code></li></ul><blockquote><p><strong>Note:</strong> This is an opt-in feature. Static analysis is only performed on mutants that escape the test suite, ensuring optimal performance.</p></blockquote><h3 id="static-analysis-tool-options" tabindex="-1"><code>--static-analysis-tool-options</code> <a class="header-anchor" href="#static-analysis-tool-options" aria-label="Permalink to &quot;`--static-analysis-tool-options`&quot;">​</a></h3><p>Specify additional options to pass to the static analysis tool (e.g. memory limit).</p><p>Example: <code>--static-analysis-tool-options=&quot;--memory-limit=-1 --stop-on-error&quot;</code>.</p><h3 id="formatter" tabindex="-1"><code>--formatter</code> <a class="header-anchor" href="#formatter" aria-label="Permalink to &quot;`--formatter`&quot;">​</a></h3><p>This is a name of console output formatter. Possible values are: <code>dot</code>, <code>progress</code>. Default is <code>dot</code> formatter.</p><h3 id="dots-per-row" tabindex="-1"><code>--dots-per-row</code> <a class="header-anchor" href="#dots-per-row" aria-label="Permalink to &quot;`--dots-per-row`&quot;">​</a></h3><p>Number of dots per row in the dot progress formatter. Use <code>&quot;max&quot;</code> to fit the terminal width.</p><p>Accepted values: a positive integer (e.g. <code>--dots-per-row=80</code>) or the literal <code>&quot;max&quot;</code> (e.g. <code>--dots-per-row=max</code>). Default is <code>50</code>. Only applies when the <code>dot</code> progress formatter is in use.</p><div class="language-shell vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">shell</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --dots-per-row=80</span></span>
<span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --dots-per-row=max</span></span></code></pre></div><p>With <code>&quot;max&quot;</code>, the formatter fits as many dots as the terminal width allows after reserving room for the <code> (current / total)</code> suffix on the right, and never exceeds the total mutation count when it is known.</p><blockquote><p>This option can also be set in <a href="/guide/usage.html">configuration file</a> as <code>dotsPerRow</code>. The CLI flag takes precedence over the configuration file value.</p></blockquote><h3 id="log-verbosity" tabindex="-1"><code>--log-verbosity</code> <a class="header-anchor" href="#log-verbosity" aria-label="Permalink to &quot;`--log-verbosity`&quot;">​</a></h3><p>The verbosity of the log file, <code>all</code> - this mode will add “Killed mutants” into log file and add additional information, <code>default</code> - normal mode will skip “Killed mutants” section in the log file, <code>none</code> - which will disable logging to files.</p><div class="language-shell vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">shell</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --log-verbosity=all</span></span></code></pre></div><h3 id="initial-tests-php-options" tabindex="-1"><code>--initial-tests-php-options</code> <a class="header-anchor" href="#initial-tests-php-options" aria-label="Permalink to &quot;`--initial-tests-php-options`&quot;">​</a></h3><p>Run Initial Tests process with additional php options. For example with <code>-d zend_extension=xdebug.so</code> which will run <code>Xdebug</code> only for code coverage.<br> May be useful for cases when <code>Xdebug</code> is not enabled globally. Also it’s useful from performance point of view.</p><div class="language-shell vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">shell</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">infection</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --initial-tests-php-options=</span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">&quot;-d zend_extension=xdebug.so&quot;</span></span></code></pre></div><h3 id="ignore-msi-with-no-mutations" tabindex="-1"><code>--ignore-msi-with-no-mutations</code> <a class="header-anchor" href="#ignore-msi-with-no-mutations" aria-label="Permalink to &quot;`--ignore-msi-with-no-mutations`&quot;">​</a></h3><p>Ignore MSI violations when no mutations are generated.
