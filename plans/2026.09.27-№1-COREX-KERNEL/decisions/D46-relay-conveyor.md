# D46 — Эстафета ролей и непрерывный Next (accepted)

**Actor:** repository owner (сессия 2026-09-29: «чтобы последовательность всегда была чёткой, и план знал, к чему надо идти дальше после выполнения каждой своей команды»; «как только какая-то часть делается, она коммитится и пушится»).
**Evidence:** RAG:— `session-routing.md` §Пул и роли, `roadmap.md` §Жизненный цикл, `handoff.md` после P01.4 (Next вычислялся из прозы).

## Решение

1. **Конвейер** — таблица `roadmap.md` §Эстафета: для каждого шага цикла D21/D24 — команда, роль (provider/model из пула `session-routing.md`) и Next, который этот шаг обязан записать. Роли: дизайн фазы и finish — claude-code opus; аудит дизайна — codex gpt-6-astra (не автор дизайна и не исполнитель строк); исполнение — executor строки execution-sheet; ревью — reviewer строки; закрытие фазы — executor последней строки фазы в том же root.
2. **Каждая команда заканчивается** зелёной проверкой своего контракта → коммит → `git push origin main` → переписанный `handoff.md` с одним Next по таблице §Эстафета и launch-block **той роли, которая исполняет следующий шаг** (не своей). Пуш в собственный репозиторий — часть команды; публикация (Packagist, split-репозитории, теги) остаётся owner-gate P09.
3. **Hosted CI** проверяет агент, сделавший push: `gh run watch` по run своего коммита. GREEN → Next по таблице. Красный по коду → чинит в текущем scope. Не стартовал по внешней причине (billing, runner) → Next `waiting:` с условием «GREEN CI на <sha>» и целевой командой; агент не выдумывает обход.
4. **После последней строки execution-sheet фазы** Next = `close` фазы; после закрытия — `design-phase` следующей фазы из `backlog/` (роль claude-code opus), пока backlog не пуст; после P09 — `close`/`archive` плана.
5. Next всегда один; группировка — только из execution-sheet; финиш и аудит дизайна не пропускаются.
6. **Два равноправных режима исполнения строки** (выбор владельца на запуск): (a) `task:plan-run <items>` — агент сам ведёт журнал/state/handoff; (b) обычная сессия кода: промпт = item-spec (`phases/Pnn/Pnn.m.md`) + «выполни Validation, закоммить, запушь, ничего в `plans/` не меняй»; затем claude-code opus делает `reconcile` в план (state, journal, Completion Notes по выводу Validation и коммиту, handoff Next по §Эстафета). Результат и следующий шаг одинаковы.

## Почему

Раньше Next после закрытия фазы выводился агентом из прозы жизненного цикла; роль следующего шага (кто проектирует, кто аудирует) не была закреплена, и agent мог выдать launch-block своей модели. Таблица делает эстафету механической.

## Consequences

`roadmap.md` §Эстафета, `session-routing.md` (launch Claude для дизайна), handoff P02 → аудит astra. Плановое правило «push — owner» (plan §2) уточнено: push в `main` своего репозитория — часть каждой команды.
