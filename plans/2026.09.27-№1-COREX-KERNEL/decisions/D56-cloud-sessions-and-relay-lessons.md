# D56 — Облачные сессии и уроки эстафеты (accepted)

**Actor:** repository owner (сессия 2026-09-29: выбран вариант C — «в облачную сессию передаём только кодовую разработку»; «надо делать выводы и фиксировать их, чтобы в дальнейшем не было проблем»).
**Evidence:** RAG:— эта сессия: P02 оставлена с пустым Phase Handoff и невалидным `handoff.md` (plan-lint 5 ошибок, Next `plan-close`); облачная сессия Claude не видела приватный `axiomasoft/corex` (в организации были установлены только GitHub Apps `cursor` и `chatgpt-codex-connector`), `academici/corex-mirror` устарел (последний коммит 2026-09-19); коммит плана автора дизайна пересёкся с активной работой Codex по P02 и был откатан (`b61283e`); облачный скан P03 (`1350c1c`) воспроизводится байт в байт.

## Solution

1. **Вариант C — один писатель плана.** Носители плана (`plans/…`: phases, state, journal, handoff, roadmap, decisions, generated views) меняет только автор плана (claude-code opus) локально с пакетом Task. Облачные и локальные сессии кода получают промпт + файл задания в плане и пишут только код продукта (или свой каталог выхода `artifacts/<Pn>-design/cloud/` для сбора фактов) в свою ветку; автор плана забирает ветку (`git merge --ff-only`/cherry-pick), перезапускает проверки и сводит результат в план.
2. **Задание облаку** — файл в плане (образец `artifacts/P03-design/cloud-brief.md`): что читать, что сделать, детерминированный скрипт, проверки перед сдачей, ветка, формат ответа; факты отделены от решений. Облаку нужны только `git` и `python3`; MCP, Perplexity и Task — только у автора плана локально.
3. **Доступ облака:** для приватного `axiomasoft/corex` в организации `axiomasoft` установлено GitHub App Claude (или используется Codex cloud, у которого App уже есть). `academici/corex-mirror` не использовать — не синхронизирован.
4. **Старт любой команды плана** (дизайн, исполнение, закрытие): `git fetch` + `git status` (дерево = `origin/main`), `plan-lint` и `design-context`/`design-gate`. Незакрытая фаза или невалидный handoff предыдущего шага сначала закрываются/чинятся тем, кто их обнаружил, отдельным коммитом, до своей работы.
5. **Конец любой команды исполнения:** если закрыт последний item фазы — та же сессия закрывает фазу (Phase Handoff + closure) и оставляет `handoff.md`, проходящий `plan-lint`, с одним Next и launch-block/промптом следующей роли.
6. **Пауза владельца** («погоди», «не меняй») останавливает запись в план и пуш немедленно; параллельно с активной работой другого агента по плану автор не коммитит носители плана.

## Why

Каждый пункт закрывает реальный сбой этой сессии; единственный писатель плана исключает конфликты `handoff.md`/journal между агентами, а облако без Task не может создавать валидные носители (они генерируются и проверяются Python-инструментами Task).

## Consequences

Все последующие фазы (P03–P09): облачные запуски — по заданию-файлу и промпту в `handoff.md` (Next `manual`), реконсиляция — автор плана. `session-routing.md` §Эстафета читается вместе с этим решением.
