# D78 — P10: уточнения второго дизайна перед исполнением

**Actor:** author-choice designer/codex/GPT-6 в разрешённом finish (D77, plan §2 B6).
**Evidence:** RAG:— `phpstan-tests-lint.neon:48`; `.github/workflows/ci.yml` quality/auth-tests/packages-tests; `scripts/php84`; `scripts/run-root-tests.sh`; `packages/core/src/Attributes/Internal/{SourceType,SurfaceScanner}.php`; `packages/tools/src/Internal/{ToolSchemaSupervisor,ToolSchemaWorker}.php`; досье/примеры P10. Исследования D74/D76 переиспользованы, новых внешних решений нет.

## Решение

1. **Один локальный рецепт установки.** `ci-local.sh` ставит root и `packages/access` после stancl staging, применяет Pest `^4.7` для Laravel 12, передаёт `--with` массивом Bash. Без аргументов исполняет объявленные гейты; аргументы — конкретная команда в той же чистой копии. P10.2 проверяет манифесты в обоих Laravel-лейнах через этот рецепт, без частичной установки, забывающей D42. Проверяется committed HEAD: кандидат коммитится перед прогоном; cleanup удаляет worktree, stash не используется.
2. **Герметичная проверка без управления общей БД.** `test:hermetic` задаёт `PGSQL_HOST=127.0.0.1`, `PGSQL_PORT=1`, `PGSQL_DATABASE=corex_test`: PG недоступен этому процессу и пропуск по отсутствующему имени *_test не маскирует ошибку группы. Останавливать общую PostgreSQL не требуется. Перенос теста в `pg` сохраняет его фактическое исполнение PG-лейном.
3. **Манифест сохраняет собственные объявления.** D74 означает владельца пакета, не только текущий файл класса: собственные public/protected methods/properties/constants, promoted properties, enum cases, наследование и трейты внутри того же пакета сохраняются. Внешние родители/трейты не разворачиваются; прямые связи записываются FQCN. `extends`, `implements`, `uses` — отдельные списки, без trait в `extends`; class extends содержит не более одного имени, interface extends — сортированный список. Собственный override приоритетен. Набор собственных объявлений до правки снимается AST по файлам пакета и сравнивается с соответствующей проекцией результата, без vendor-членов исходного манифеста. Это уточнение D74, не расширение Api/Spi.
4. **Worker: готовность, ограниченное ожидание, cleanup.** `ready\n` отправляется после autoload и создания валидатора, до чтения stdin. Supervisor использует монотонные часы; стартовые 5 секунд и валидационные 100 мс не меняются. Бюджет валидации начинается до отправки запроса, ограничивает и частичную запись. До ready — `schema_unavailable`; после ready transport/формат/дедлайн/память — `schema_limit`. Только ответ ожидаемой формы допускает успех. Потоки неблокирующие, ready разбирается отдельно с сохранением остатка; stderr дренируется с ограничением сохраняемой диагностики. Cleanup в finally прекращает живой процесс, при необходимости принудительно убивает после ограниченного ожидания, закрывает pipes и reap; `proc_close` не ждёт бесконечно живой worker.
5. **Проверки нового протокола.** Кроме четырёх основных сценариев — повреждённый/оборванный ответ и ready по частям. Фикстуры возвращают PID; завершение проверяется до закрытия process resource либо по PID после cleanup, без `proc_get_status` закрытого ресурса. Тестовый phpBinary-wrapper может подменить последний аргумент worker fixture; публичный ToolSchemaValidator не меняется.
6. **Постепенная приёмка CI.** P10.1–P10.3 принимаются по своим джобам/шагам с поимённым перечнем остаточных отказов и владельцами следующих items. Новый отказ не теряется. P10.4 закрывает workflow со conclusion success; event-skipped Mutation registry допустим по D76. «Все джобы success» в кратких носителях читается в этом смысле.

7. **Закрытые развилки.** JsonDocuments в tasks-workflow вызывается полным FQCN (поздний use убирается); ext-redis объявляется в suggest с extension guard существующего isolated Redis теста. PG-методы webhooks остаются в текущих файлах и получают #[Group("pg")]; root test:pg доказывает их исполнение. Сохранённый H2 RED переиспользуется: изменяемое число находок до ремонта не является входным acceptance threshold.

## Почему

Рецепт без access не воспроизводит tests-lint; частичная установка Laravel 12 теряет известный Pest override. Сравнение манифеста с vendor-членами не доказывает полноту собственных деклараций. Неопределённые framing/cleanup оставляют worker риск зависания и неверного успеха. Уточнения закрывают эти конкретные риски без новых фаз.

## Consequences

Уточняются P10 dossier/examples/items и roadmap. Новых items и обязательного повторного ресерча нет. Coverage и остаточные отказы Laravel 12/PHP 8.5 выясняются P10.4 по отчётам.
