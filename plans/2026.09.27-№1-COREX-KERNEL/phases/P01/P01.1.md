### P01.1 — Окружение PHP 8.4 и платформа манифестов

**Intent:** Сделать PHP 8.4 воспроизводимым окружением исполнения (`scripts/php84`), зафиксировать baseline метрик на
исходных манифестах и поднять все 21 installable корень до D03/D36/D37: PHP `^8.4`, Laravel `^12.0|^13.0` (включая access),
`minimum-stability: stable`, lockstep `branch-alias 1.0.x-dev` + `^1.0@dev`, полное монорепо-замыкание в каждом корне,
Pest 5 / PHPUnit 13 / Testbench `^10.12|^11.3` — с зелёными sqlite, pg, per-package и Laravel 12 лейнами.

**Why:** D03 (PHP ^8.4, access L13 — F00 A2.3/A12.2), D16/D36 (stable, без unbound `@dev` — A12.1, `validate --strict`),
D37 (стек); plan §2 «окружение исполнения» (A12.7). Pest 5 требует PHP 8.4 (E1) — без окружения P01.2–P01.4 не исполнимы.

**Scope Included:** `scripts/php84` (examples §1); `artifacts/P01/baseline-metrics.json` (junit-summary по лейнам sqlite,
tasks-workflow, pg + число ошибок PHPStan level 6 + список падающих тестов) на исходных манифестах под PHP 8.4; правки
`composer.json` root и 20 пакетов по `manifest-check.py`; `composer.lock` под PHP 8.4; `scripts/manifest-check.py` (копия
plan-скрипта) + composer-скрипт `manifests:check`; исправление падений тестов, вызванных PHP 8.4 / Pest 5 / PHPUnit 13; root dev install access + AzGuard (разрешённое D36 исключение, golden P01.2 отражает все пакеты);
docs: требования PHP 8.3 → 8.4, команда разработки через `scripts/php84`.

**Scope Excluded:** PHPStan-конфиги и уровень (P01.3); CI (P01.4); golden (P01.2); Rector-сеты; stancl/azguard (P07);

**Implementation Rules:**
- Runbook досье §4.1 шаги 1–9 строго по порядку; шаги 1–3 — preflight: при провале — стоп и эскалация O-1/O-2 с точной
  командой из §7, никаких прогонов на PHP 8.3.
- Baseline (шаг 4) снимается **до** правок манифестов, на `composer install` из текущего lock под PHP 8.4.
- Правки манифестов — только перечисленные `manifest-check.py` коды; `require-dev` инструментов не добавлять туда, где их нет
  (кроме root). Исключения D36 п.3 — ровно как в `ALLOWED_PRERELEASE`.
- `repositories.stancl-providers` никогда не коммитится (снимать `composer config --unset …`).
- Падения тестов на 8.4 исправляются в коде/тестах; skip, понижение `--min`, удаление тестов запрещены (anti-weakening).
  >20 разнородных падений или падение с неясной причиной в продуктовой логике → эскалация (K3).
- Комментарии в коде — только «почему»; без ссылок на план, кроме квалифицированных `PLAN3.D36` при необходимости.

**Code Guidance:** `scripts/php84` — дословно examples §1 (проверен на хосте). `scripts/manifest-check.py` — копия

  пакет → exit 1 со строкой `mono-constraint`, затем откат → exit 0.

  `scripts/php84 composer test:packages` → exit 0; `scripts/php84 composer lint:check` → exit 0.
- `scripts/php84 composer analyse` → число ошибок ≤ `phpstan_level6_errors` из baseline-metrics.
- `python3 plans/2026.09.27-№1-COREX-KERNEL/artifacts/P01-design/scripts/junit-summary.py sqlite=… tasks-workflow=… pg=… --compare plans/2026.09.27-№1-COREX-KERNEL/artifacts/P01/baseline-metrics.json` → exit 0 (тестов не меньше, падений не больше).
