### P01.4 — CI supply chain и подключение страховочной сетки

**Intent:** Привести три workflow к D18/D39: все actions по полному SHA с комментарием версии (pinact), `permissions: {}` +
минимальные job-гранты, `persist-credentials: false`, блокирующий zizmor, Dependabot, CODEOWNERS, `composer validate --strict`
и `composer audit --locked`, матрица PHP 8.4/8.5 × Laravel 12/13 и PostgreSQL 16/18 — и подключить в CI гейты P01.1–P01.3
(manifests, golden, ownership, per-package PHPStan + ceilings, dependency-analyser).

**Why:** D18 (F00 A12.3–A12.5), D37 п.5–6 (PG, матрица без 8.3), D39 п.3; страховочная сетка должна исполняться на каждом
push, иначе P02–P08 проверяются только локально.

**Scope Included:** `.github/workflows/{ci,distribution-proof,remaining-cohort-proof}.yml`; `.github/dependabot.yml`;
`.github/CODEOWNERS`; `.github/zizmor.yml` (только обоснованные ignore); обновление actions до E6 (checkout v7.0.1,
setup-php 2.37.2); удаление PHP 8.3 и шага «Boxed profile»; PG-матрица; audit/validate шаги; jobs `manifests`, `golden`,
`ownership`, `dependencies`, `zizmor`; шаг PHPStan в `quality` → `composer analyse`; ссылки docs на CI-лейны, если есть
(`grep -rn "8\.3\|Boxed profile" docs .github`).

**Scope Excluded:** release-job и SBOM (P09); блокирующий Roave (P09, остаётся report-only); push, merge, настройки
репозитория и секреты (owner, O-3); изменение DoD-скрипта PLAN2 (`dod-1.0.py`) кроме случаев, когда он ломается на новой матрице.

**Implementation Rules:**
- SHA проставляет `pinact run` (не вручную); формат `@<40-hex> # vX.Y.Z`.
- Каждая job — явный `permissions` с минимумом (`contents: read`); `write`-гранты не вводятся.
- Каждый `actions/checkout` — `persist-credentials: false`.
- `${{ … }}` из недоверенных контекстов не подставляется в `run:` напрямую — через `env:` (zizmor `template-injection`).
- zizmor-ignore — только в `.github/zizmor.yml`, каждый с причиной; `continue-on-error` запрещён (anti-weakening).
- Все install-шаги сохраняют `stage-stancl-providers.py` перед `composer update` (P07 уберёт).
- Инструменты для локальной проверки (zizmor, pinact) — в `build/tools/` (gitignored), версии E6, pinact с проверкой checksum.

**Code Guidance:** Before/after job, новые jobs, dependabot/CODEOWNERS/zizmor — examples §8.1–§8.3. Порядок: pinact →
permissions/persist-credentials → матрицы → audit/validate → новые jobs → zizmor-прогон и исправления → Dependabot/CODEOWNERS.
Входы `zizmor-action` (`advanced-security`, `persona`) — сверить с README action на pin-SHA (VERIFY-AT-EXEC, E6).

**Validation:**
- `bash -c 'uses=$(grep -hE "^\s*-?\s*uses: " .github/workflows/*.yml) || exit 1; bad=$(printf "%s\n" "$uses" | grep -vcE "@[0-9a-f]{40} # v?[0-9]"); rc=$?; printf "%s\n" "$bad"; test "$rc" -le 1 && test "$bad" -eq 0'` → `0`, exit 0; неполный pin или ошибка чтения → exit 1.
- `grep -L "^permissions: {}" .github/workflows/*.yml` → пусто; `grep -c "persist-credentials: false" .github/workflows/*.yml`
  = числу `actions/checkout` в каждом файле.
- `build/tools/venv/bin/zizmor --offline .github/workflows` → exit 0.
- `build/tools/venv/bin/python -c "import yaml,glob;[yaml.safe_load(open(f)) for f in glob.glob('.github/**/*.yml',recursive=True)]"` → exit 0.
- `bash -c 'if grep -nE "[[:punct:]]8\.3[[:punct:]]|Boxed profile" .github/workflows/*.yml; then exit 1; else test "$?" -eq 1; fi'` → пусто, exit 0; устаревшая матрица/шаг или ошибка чтения → exit 1; `grep -n "matrix.postgres" .github/workflows/ci.yml` → ≥1.
- `grep -c "composer audit --locked" .github/workflows/ci.yml` ≥ числа шагов `composer update|install` в ci.yml.
- Локальный эквивалент новых jobs зелёный: `python3 scripts/manifest-check.py`, `scripts/php84 composer golden`,
  `scripts/php84 php scripts/ownership-gate.php`, `scripts/php84 composer analyse`, `scripts/php84 bash scripts/dependency-analyser.sh --all`,
  `scripts/php84 composer audit --locked` → exit 0 каждый.
- `bash scripts/anti-weakening-gate.sh` → exit 0.
- Independent review: reviewer/effort — из строки `roadmap.md` `execution-sheet/v1`; свежий контекст, reviewer model !=
  executor; вход — item-spec + diff + вывод Validation; строка `review: <provider>/<model> <GREEN|findings:N>`; ≤2 раунда.
- Live CI — не acceptance item: владелец пушит (O-3), результат — Phase Validation.

**Deliverables:** захардененные workflow с новыми jobs, Dependabot, CODEOWNERS, zizmor-конфиг; Completion Notes: число
pinned actions, список новых jobs, zizmor findings до/после, review; в Phase Handoff — запрос O-3 (push + ссылка на run).
