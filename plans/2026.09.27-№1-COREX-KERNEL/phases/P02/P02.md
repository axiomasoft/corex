## Phase Context

P02 приводит монорепо к glossary P00.1 без изменения наблюдаемого поведения. Сначала швы в текущей раскладке:
ядро перестаёт знать пакеты (D27 `FieldCastRegistry`, D28 SavedViews-wiring в panels, D32 `ManifestSectionCompiler`,
`ConfigReportSection`, `ImpersonationGuard`), кросс-пакетные тесты уходят с `Internal` на `Testing`-харнессы (D35),
operations отдаёт webhooks/tools через SPI и собственный провайдер (D31). Затем один механический перенос
инструментом по картам P00 (D44): vendor `axiomasoft`, merge modules → ядро, split operations → operations/tools/webhooks,
attributes → custom-fields, access → `CoreX\Access`, `CoreX\Search\Meilisearch` → `CoreX\SearchMeilisearch`, зоны ядра →
закрытый список модулей, один PSR-4 корень на пакет, удаление import-export, `flex/crm` → `products/flex-crm`.
Последним — идентификаторы пакета (config/tags/env/команды, D33/D45), гейт полноты переименований и ownership `--strict`.

## Pitfalls

- Все PHP-команды — `scripts/php84`; `stage-stancl-providers.py` ключ `repositories.stancl-providers` снимать после install/update (P01).
- Швы не меняют вывод: `corex:config:validate`, `api/v1` снимок, golden `routes/events/wire` — байт в байт; литерал регрессионного теста и baseline не правятся «под зелёное».
- Новые файлы швов — в текущей раскладке и с текущим namespace каталога; строка карты — из `new-map-rows.tsv`, `check-maps.py` exit 0 после item.
- Перенос P02.3 — только инструментом; результат переноса руками не правится (кроме остатка, названного гейтом полноты); дефект → скрипт/карта → новый сухой прогон.
- Golden в P02.3/P02.4 не перезаписывается; потолки и ownership baseline только сокращаются (группы преемников D44 п.6).
- `tenancy` config-ключ и `tenancy.php` не переименовываются (D45 п.2); меняются только env внутри файла.
