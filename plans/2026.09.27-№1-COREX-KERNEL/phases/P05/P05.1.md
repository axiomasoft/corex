### P05.1 — Typed Options, runtime-проверки и удаление static Config

**Intent:** Дать каждому пакету с config-файлом типизированный immutable Options, который читается один раз и проверяется по форме при загрузке; вынести проверки, требующие runtime-окружения, в отдельный слой, срабатывающий до приёма работы процессом; удалить static `CoreX\Config\Internal\Config` и закрыть чтение config вне границы composition.

**Why:** D08, D69, D72. Options сегодня пересобираются на каждый `make()`; 11 пакетов читают массив по ключам; гейт не видит обращений к config repository; 132 ссылки на static `Config` живут в миграциях, тестах и скриптах. Сборка образа не должна требовать секретов, а процесс не должен начинать работу без них.

**Scope Included:** 11 новых внутренних `<Pkg>Options` (D69 п.1) с тестами формы; lazy `singleton` и резолв в `boot()` для всех Options; значения в конструкторы сервисов вместо repository (4 runtime-читателя, 2 tenancy-команды); поля `ApiOptions` и `CoreOptions::acknowledgedDangerousModes`; `RuntimeConfigCheck`, `RuntimeConfigGate`, проверки опасных режимов четырёх пакетов и наличия секретов; расширение `corex:config:validate`; удаление `Config.php` и замена 134 ссылок; гейт `config-composition` C1–C4, `OptionsSingletonTest`, `BuildStageBootTest`; правка `table-write-ownership-gate` и mutation-патча; Golden delta.

**Scope Excluded:** Деление providers, фабрики и анонимные классы (P05.2); фасады, хелперы, время жизни биндингов (P05.3); генерация `configuration.md`, `config:cache`, конституция (P05.4); перенос существующих Options; имена таблиц и миграционная схема (P08); `tenancy` Impersonation (P07).

**Implementation Rules:** Дефолт каждого ключа равен значению config-файла базового commit; поведение по умолчанию не меняется. `fromArray` проверяет только форму и проходит на пустом окружении; наличие секрета и опасные режимы — только `RuntimeConfigCheck`. Все нарушения одного Options — в одном `InvalidConfiguration`; секретные значения в сообщения не попадают. Новый Options — `@internal` в `src/Internal/`, без `#[Api]`; сервис получает значения, а не Options. Реализация `RuntimeConfigCheck` — тип слоя композиции: ей, как provider и registrars, разрешено читать Options своего пакета (D76). Options не биндится через `bind` или `instance` в `register()`. Static `Config` не заменяется другим static-доступом. Валидация не ослабляется ради теста: тест дополняет config. Allowlist гейта — ровно D69 п.6; список опасных режимов и build-команд — ровно D69 п.7 и п.10; acknowledgement — только точный путь. Golden baseline — только через reviewed semantic delta (D64); слой routes байт-идентичен. Документация и CHANGELOG пакета — в этом же item.
