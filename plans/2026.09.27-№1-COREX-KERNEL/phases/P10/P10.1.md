### P10.1 — Герметичный CI-рецепт и диагностируемые гейты

**Intent:** Убрать из hosted CI отказы, вызванные самим рецептом и скриптами, а не продуктом: изменение манифестов шагами CI, недостающие установки, несовпадение клиента PostgreSQL, зависимость `bc-check` от отсутствующего инструмента, немой отказ arch-тестов, устаревший `contract-guard`. Дать локальный сценарий, воспроизводящий CI.

**Why:** D73, D74 п.6–9. Реестр H3, H4, H7, H9, H10, H11, H12: эти отказы не говорят о коде ничего и закрывают собой настоящие. Отказ `PackageGraphTest` в логе CI содержал только код возврата — причину пришлось воспроизводить.

**Scope Included:** `composer update --with` вместо `composer require … --no-update` для версий Laravel; установка `packages/access` в джобах `quality` и `packages-tests`; клиент PostgreSQL 18 в tenancy-джобе; пользователь в healthcheck; ремонт `scripts/bc-check.sh` и имя шага; вывод гейта в сообщении arch-тестов; `contract-guard` с триггером по `php-api.json`; разделы `Unreleased` CHANGELOG 20 пакетов и продукта; `scripts/ci-local.sh` и composer-скрипты `ci:local` и `test:hermetic` (определение скрипта; зелёным его делает P10.4, D76).

**Scope Excluded:** Формат манифестов, перенос tooling, зависимости (P10.2); worker схем (P10.3); группы тестов и покрытие (P10.4); установка из `composer.lock` и stancl-staging (P07); новые actions и изменение SHA-pin; workflows `distribution-proof`, `remaining-cohort-proof`.

Редактируемый workflow CI читается как часть Files.

**Implementation Rules:** Шаг CI не изменяет отслеживаемые файлы ради версии; исключение — Pest `^4.7` в лейне Laravel 12 (D42). Существующие SHA-pin actions и блоки `permissions` не меняются; новые actions не добавляются. Ни один джоб и ни один шаг не удаляется и не переводится в `continue-on-error`. Запись CHANGELOG описывает фактические изменения публичной поверхности пакета, а не формальную строку. Рецепт CI локально выполняется только через `scripts/ci-local.sh` в чистой копии committed HEAD; кандидат коммитится перед прогоном. Установка включает root и packages/access; Laravel 12 получает Pest ^4.7; аргументы скрипта задают команду в установленной копии (D78). Отказ джоба, принадлежащего P10.2–P10.4, не чинится здесь и не скрывается.

**Code Guidance:** Досье §3.1 шаги 1–11; `examples.md` §1 (сообщение отказа arch-теста), §2 (`ci-local.sh`). Проверки V1–V3 раннера — `research/P10-design-rag.md`; временный диагностический шаг V1 удаляется до закрытия item.

**Validation:**

- `grep -c -E 'require "(illuminate/contracts|laravel/framework):' .github/workflows/ci.yml` → `0` (при срабатывании V3 — только шаги лейна Laravel 12, число и причина в Completion Notes); `grep -c -- '--with "' .github/workflows/ci.yml` → число не меньше числа удалённых шагов.
- `grep -c 'continue-on-error' .github/workflows/ci.yml` → не больше, чем на базовом commit; `git diff <база> -- .github/workflows/ci.yml` не удаляет ни одного `name:` джоба.
- Без `rg` (заглушка по `examples.md` §2): `PATH="build/no-rg:$PATH" scripts/php84 composer bc-check` из корня репозитория → exit 0; `git grep -n -w rg -- scripts/bc-check.sh` → нет совпадений (Git exit 1).
- `bash scripts/contract-guard.sh ea0b024` → для каждого пакета строка `changed WITH CHANGELOG — OK`, exit 0; `git grep -n 'src/Contracts' -- scripts/contract-guard.sh` → нет совпадений (Git exit 1).

Основное дерево после запусков без изменений: `git status --short` не содержит `composer.lock` и `composer.json`.
