# P1 — Ядро CoreX: примитивы + модульная система (roadmap P0 / B-10)

## Phase Context

Реализует блупринт **B-10** (`Vaults/Brain/plans/flex/30_blueprints/B-10_core-module-loader.md`):
примитивы ядра + полноценная модульная система. Стоит на текущем `corex/core` (BaseModel,
MoneyCast, ID-seam, простые EntityRegistry/Settings/Audit — расширяем, НЕ переписываем). Ключевое
решение фазы (D2): модуль-система выносится в **новый пакет `flex/modules`** (namespace
`Flex\Modules\`), существующие EntityRegistry/ModuleRegistrar из `corex/core` мигрируют туда.

Что фаза считает завершением: модуль объявляется манифестом, обнаруживается `flex:modules:compile`
из `installed.json`, компилируется `RegistryCompiler` (8 extenders), включается/выключается/
вычищается через `ModuleLifecycle`-FSM с предсказуемым purge по `mod_records`; EntityRegistry v2
отдаёт `EntityDefinition` с capabilities; Settings/Audit v2 на таблицах `sys_*`; заведены
departments (ltree), feature-flags, pubsub, DomainEvent, контракты TenantContext (реализация — P2).

**Вне фазы (D6):** `corex/components` (B-10 §3.5) отложен — потребитель FlexCMS в roadmap-P5.
**Вне фазы (D26):** B-10 §4.5 DX-генераторы (make:module/make:entity, flex:modules:why) и §4.6 MCP
dev-сервер + AC-33/AC-34 + AC-12 N−1 CI-прогон — отложены (потребитель — DX-волна после ядра);
component-tied части покрыты D6. Все `sys_departments` FK на `workspace_id`/`users` добавляются
миграциями P2 (межпакетный порядок). **Тест-файлы всех items — в корневом `tests/`** (phpunit.xml
testsuites; пакетные packages/*/tests НЕ подключены к раннеру — D19).

**Порядок исполнения (внутри фазы):** items идут по номерам, КРОМЕ **P1.12** (контракты
TenantContext/AccountRef/WorkspaceRef — чистые DTO без зависимостей): он ПРЕДПОСЫЛКА `DomainEvent.tenant`
(P1.9) и scope Settings/Audit — исполнять сразу после P1.1, до P1.7. **Namespace-канон (D11):**
corex/core = `CoreX\` (существующий), модуль-система = новый пакет `flex/modules` / `Flex\Modules\` (D2).
**PG-first (D12):** миграции `sys_*`/`mod_*` — PostgreSQL 16 (ltree/BRIN/jsonb/advisory-locks); PG-лейн
вводит P1.6 (docker PG + `pgsql`-коннекшен + Pest `->group('pg')`), P1.7/P1.8/P1.10/P1.11 переиспользуют.
