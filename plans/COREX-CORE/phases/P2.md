# P2 — Tenancy & Auth (roadmap P1 / B-11)

## Phase Context

Реализует блупринт **B-11** (`Vaults/Brain/plans/flex/30_blueprints/B-11_auth-tenancy.md`) +
ресёрч **R-11** (stancl-readiness): двухуровневая tenancy (физическая DB-per-account на
**stancl/tenancy v4** + логический workspace) и auth (AzGuard-надстройка, entity-scoped RBAC,
OIDC/boxed-Fortify). Новый пакет **corex/tenancy** (`packages/tenancy`, `Corex\Tenancy\`; импорт
`Stancl\*` разрешён ТОЛЬКО здесь — D13) и надстройка в **corex/auth**. Tenancy-КОНТРАКТЫ живут в
corex/core (`CoreX\Tenancy\Contracts\*`, D13), их cloud-реализации — в corex/tenancy. Замещает
собственный row-level каркас `corex/core` (`TenantService`/`TenantScope`/`BelongsToTenant`)
физической моделью — ADR-004 переписан (D1); старый каркас в P1 НЕ трогался, замещается здесь.

**Первый item — блокирующий PoC-гейт (P2.1):** stancl v4 не зарелижен (0 тегов на 2026-07-12,
RAG:✅ findings/P1-P2-rag-verification-2026-07-12.md §1), 7 сценариев должны быть зелёными ДО любого
tenancy-кода. Пин `dev-master#<sha> as 4.0.0` (D8) + supply-chain-якорь (D25). **Предусловие гейта —
OQ-5: stancl master требует `php ^8.4` при CoreX `^8.3` — решение владельца ДО P2.1.** Ни один item
P2.2+ не стартует без GO (Status Board не двигается). Pre-mortem фазы (18 причин, митигации внесены
в items) — findings/P2-premortem.md; подтверждённые находки аудита — findings/P1-P2-audit-2026-07-12.md.
Тест-файлы items — в корневом `tests/` (D19).

**Порядок исполнения (внутри фазы):** P2.1 (гейт) → P2.2 (root-схема, central DB) → P2.3 → P2.4 →
P2.5 → **P2.7 (users) до P2.6/P2.8** (тенант-таблица `users` — FK-зависимость `wsp_workspace_members`/
`wsp_invitations` (P2.6) и `aut_role_assignments` (P2.8): её миграция несёт самый ранний тенант-DB
timestamp) → P2.6 → P2.8 → P2.9 → P2.10 → P2.11 → P2.12 → P2.13. root_ миграции — на **центральном**
коннекшене; `wsp_*`/`aut_*`/`users` — внутри тенант-БД (golden-шаблон). PG-лейн из P1.6
переиспользуется (D16): docker PG16 + `pgsql` + Pest `->group('pg')`.

Завершение фазы: аккаунт провижинится клоном golden-шаблона (без миграций на лету), резолвится
host→account→workspace→scope, роли компилируются из матрицы в AzGuard, entity-scoped RBAC
накладывает WHERE по эффективному scope, boxed-режим работает без stancl (SingleAccountResolver +
Fortify). Опирается на контракты P1.12 (TenantContext) и P1.10 (sys_departments для dept-scope).
Cross-package FK (users↔sys_departments↔wsp_workspaces, конфликт C4) — отдельной integration-миграцией
(P2.6, D14).
