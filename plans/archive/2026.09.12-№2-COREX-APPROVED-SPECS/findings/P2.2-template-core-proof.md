## Implemented surface

- Additive root migration
  `2026_09_12_200001_add_schema_hash_to_root_templates_table.php`
  (`95143c7c0c8b91a16136fc56c5d8453e0b9f7d0dec357d72a4119c45bebc4373`)

- `SchemaCatalogueSerializer` (`972c19e6bbfa26aba3658f7743d864fe64692508c88364763b6906b8ed7c5d5b`)
  produces a deterministic read-only PostgreSQL catalogue encoding and SHA-256.
  Physical identity, data and mutable sequence state are absent from the
  projection.
- `TemplateManifest`, `TemplateIntegrityVerifier`, and
  `TemplateIntegrityLock` authenticate an Ed25519 manifest, acquire the
  transaction-scoped qualified template lock, and require
  expected-manifest hash = recorded row hash = actual catalogue hash before
  returning a template. No provisioning, clone, pool, lifecycle, or wave
  consumer is changed by this item.
- Empty `trusted_keys`/`manifests` configuration is fail-closed. Test-only
  manifests are signed by an in-memory Ed25519 key in `TestCase::trustTemplate`.
