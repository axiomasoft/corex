# P2.3 — Integrity gate on every early write seam

**Date:** 2026-09-14. **Status:** GREEN for the local CoreX implementation and
isolated PostgreSQL fixture. No production template, signing key, role, or
operator configuration was changed.

## Entry-point map

| Entry point | Integrity check before the first mutation |
| --- | --- |
| `StanclTenantDatabaseProvisioner::provision()` | `assertCurrent()` before account `forceFill()->save()` and `TenantCreated` |
| `PendingPool::cloneOne()` | `assertCurrent()` before `Account::create()` |
| `PendingPool::pullPending()` | `assertAccount()` before the `pending → provisioning` claim |
| `CreateDatabaseFromTemplate::handle()` | reloads the central account and calls `assertCurrent()` before the existing-DB branch; `assertAccount()` before its no-op |
| `TemplateClonePostgreSQLManager::createDatabase()` | `assertCurrent()` before backend termination, `CREATE DATABASE`, `GRANT`, or `ALTER DATABASE` |
| `AccountLifecycle::startTrial()`, `activate()`, `resume()` | `assertAccount()` before status/domain/event writes |
| `MigrationWaveOrchestrator::runBatch()` | verifies every non-deleted target before `running`, target-state, or per-account writes |

`TemplateIntegrityVerifier::assertAccount()` now compares the actual account
catalogue hash to the independently authenticated template hash. The queue
uses a fresh central `Account` row rather than serialized job data, so a
changed cluster/template context is rejected after queue delay.

## Residual operator invariant

The implementation intentionally fails closed when trusted keys/manifests,
the recorded hash, the template catalogue, the account catalogue, or cluster
admission do not match. A production deployment still needs its separately
owned immutable manifest distribution and PostgreSQL privilege/seal setup; no
fallback to an unverified ready template exists.
