# P4.1 — Проверенные локальные источники tenancy/jobpipeline

P4.1 выполнен как локальная подготовка. Выбрана прозрачная схема: собственные имена в axiomasoft, предварительные версии и неизменные выбранные upstream commits. Готовы точный metadata patch, полные снимки исходников, воспроизводимые ZIP-кандидаты и контрольные суммы. Это не опубликованные пакеты и не доказательство установки у чистого потребителя.

## Решение и владельцы

Технический выбор делегирован текущим владельцем CoreX: brief/P4.1-owner-delegation.md#technical-choices. D9 фиксирует границы и авторизацию локальной подготовки. Предлагаемый сопровождающий — Dmitry Vostrikov как текущий maintainer CoreX; организация — axiomasoft по ранее выбранной topology. Исходное авторство Samuel Štancl сохраняется. Upstream ownership не переносится; наличие GitHub репозиториев/тегов и полномочия на их создание не предполагаются.

## V-METADATA — GREEN

Точный patch меняет только два package names и tenancy require: stancl/jobpipeline 2.0.0-rc7 → axiomasoft/stancl-jobpipeline 2.0.0-alpha1. Любые остальные metadata fields, PHP/framework constraints, autoload/namespace/provider mappings и все исходные файлы сохраняются. Composer version не дублируется внутри VCS composer.json: его поставляет отдельная неизменяемая запись packages.json и будущий соответствующий tag.

Нижний граф: axiomasoft/stancl-tenancy@4.0.0-alpha1 → axiomasoft/stancl-jobpipeline@2.0.0-alpha1. Остальные upstream requirements сохранены; tenancy PHP^8.4 / illuminate support ^12|^13, jobpipeline PHP^8.0 / illuminate support ^10|^11|^12|^13. Это declarations, а не новое compatibility test/GA promise.

packages.json содержит exact name/version, source Git SHA, dist reference/SHA1 и proposed release URLs. source-map.json отдельно содержит SHA256 архивов и metadata. URLs пока являются планируемыми destinations, не доступным внешним channel. Временные локальные Git objects материализованы и проверены: parent — выбранный upstream commit, единственный Git diff file — composer.json.

## Точный следующий результат и границы

P4.2 может использовать эти sealed local candidates только после своего scoped invocation и квалификации transport/channel; source preparation не означает применение к root или чистую installation proof. Для внешнего mirrored release подготовлены exact destinations:

1. axiomasoft/stancl-jobpipeline: базовый upstream07dc54a…; применить jobpipeline composer hunk; verify tree/commit683de91c…; tag v2.0.0-alpha1; опубликовать exact jobpipeline-candidate.zip с указанным SHA256.
2. axiomasoft/stancl-tenancy: базовый upstream76e5f965…; применить tenancy composer hunks; verify tree/commit7d596a14…; tag v4.0.0-alpha1; опубликовать exact tenancy-candidate.zip с указанным SHA256.
3. Публиковать только exact static metadata mapping; новый upstream/metadata/archive требует новой нашей версии. Не передвигать/пересоздавать выпущенный tag. External targets/capabilities/exact result authorization отдельно, ни один такой шаг не выполнен этим пунктом.

Rollback local preparation: удалить только candidates и packet; live manifests/locks/vendor/source refs остаются прежними. Adoption/publication rollback и cold-update/install proofs принадлежат своим последующим items. Authoritative immutable source inputs precommitted at `cbd447a`; product/closure commit bound by journal. No vault sync or phase audit.
