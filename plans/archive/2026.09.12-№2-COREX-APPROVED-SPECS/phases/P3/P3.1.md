### P3.1 — L0 domain-trust extension SPI and verified-state lifecycle

**Intent:** Implement the approved lightweight `corex/tenancy` domain-trust SPI and trusted
state lifecycle so any Laravel consumer can supply its own proof policy without CoreX owning DNS,
TLS, HTTP routes or product semantics.

**Why:** D6 turns the previous unnamed-consumer placeholder into a reusable API: CoreX already
resolves only committed `verified_at` state, but lacks a safe extensible transition boundary.

**Scope Included:** Contracts/DTOs/coordinator/trusted writer/events; strict resolver host
normalization; generation migration; DI/config wiring; fake-driven package tests and package docs.

**Scope Excluded:** DNS/edge/TLS client, CNAME/TXT implementation, HTTP/job/CLI endpoints,
credentials, product host policy/cache keys, public verifier endpoint, consumer source edits and
live network actions.

**Implementation Rules:** Implement exactly the D6 protocol. New Contracts are interfaces only
in `src/Contracts/`; implementations remain hidden. No default proof adapter means custom-domain
verification is disabled. Use the existing event/DI extension canon, not a new extender or
monkey-patch. The DB transaction and generation are authority; cache locks are optional duplicate
work coordination only. Dispatch lifecycle notification after commit and never include raw token,
DNS answers or credentials. Schema/public contract diff carries tenancy changelog entry.

**Code Guidance:** Token is 32 random bytes and only a keyed digest persists. Verification proves
account+host+generation, consumes exactly once, locks and rechecks live state before setting
`verified_at`. Revoke/reassign clears trust, increments generation and invalidates old/new resolver
keys; invalidation failure denies. Resolver accepts only its strict normalized host and still does
zero DNS/adapter work. Fake ports prove all flows; events extend but never grant trust.

**Validation:** `composer lint:check && composer analyse && composer test && composer test:pg`;
package tenancy SQLite/PG tests; `composer test:arch`; contract guard; negative fake receipts for
replay/stale/foreign proof, malformed/reserved host, denied authorizer, race, retry, revoke,
reassign and cache failure; existing platform resolution remains green. No live DNS/TLS/edge call.

**Deliverables:** L0 SPI and internal lifecycle implementation only in listed paths; tenancy
changelog; fake-backed security/race/cache tests; no consumer adapter. A future consumer implements
the frozen ports with its own CNAME+TXT or alternate proof policy without changing CoreX.
