**Implementation Rules:** D13 pins the export input to committed source `ea7d0dbdf36b122904abba91e124018c11b939ed`, which contains the P4.2 provider reconciliation; the exporter must reject any other ref and never read the dirty checkout. Staged candidates use deterministic local-only versions `0.1.0-p4.3` and source ref equal to that commit; they are not published tags or provider claims. The exporter is stdlib Python 3.12 and its own SHA-256, policy SHA-256, package tree IDs, ZIP checksums and license inclusion are emitted in the map. Source policy is a closed allowlist, not root composer graph. Export JSON is tool policy/derived artifact metadata, not an alternate plan. CoreX lower provider versions must be exact resolvable staged candidates; altering tracked dependency constraints requires qualified spec, not hidden packaging rewrite.

**Authority:** routine

**Code Guidance:** 1. Implement explicit local-only command: python3 scripts/distribution/export.py --source-sha <approved-SHA> --staging <isolated-dir>. Resolve committed package trees, reject uncommitted source, unknown package, auth/crm or symbolic filesystem escape. Tool executable, policy and interpreter/runtime digests bound in export map; local export creates no public tags.
2. Include composer.json, src/config/migrations/resources as present, package README/CHANGELOG and MIT/license notices; root license supplied as documented artifact inclusion only if per-package absent. Explicitly exclude vendor/node_modules/.env/auth.json/cache/locks containing dev paths/global configs/credentials/source symlinks/private sibling content. Scan archive bytes/paths and metadata for prohibited leakage.
3. Released metadata has no type:path/development sibling repository; consumer root staged dist providers supply lower core/modules versions and approved stability. Preserve metadata transformation diff in source map; exact package name/version/source reference and dist checksum bound. @dev cannot be interpreted as an available provider.
4. Normalize archive path ordering/file modes/timestamps and compressor/tool parameters. Two independent staging builds of same SHA/policy/tool yield equal trees/archive checksums. Map candidate source SHA→package source tree→staged artifact tree/local ref→zip SHA256→metadata SHA256. Mark versions unpublished candidates, no claim released tag.
5. Seal test-support archives separately with exact source/test hashes: root core/modules harness is quality support, tasks/tenancy package suites owned per-package. Tests must exercise installed dist src, never load builder checkout from test autoload. No builder filesystem mount into consumer.

**Validation:** V-EXPORT: deterministic two-build tree/archive/metadata equality, exactly four allowlist members after provider qualification. V-LEAK: injected credential/path/symlink/private content or unexpected package rejected with safe filename-only diagnostics. V-GRAPH: exported root metadata resolvable through staged lower providers, no type:path/sibling dependency; tenancy requires P4.2 source evidence. V-TEST-BIND: sealed test autoload points to installed package source, no checkout shortcut. Quality-tool focused exporter tests and appropriate root lint/analyse/test; no product src mutation means no new D98 run required.

**Deliverables:** Local exporter/policy/quality tests; findings/P4.3-export-map.md exact SHA/tree/ref/artifact/tool/license/provider mapping; findings/P4.3-export-test-inputs.md sealed harness hashes and installed-source proof. Staging disposable outside git. Rollback: discard staging/disable exporter; never force-push/delete published refs.
