## Implemented local reference

- `AccountsQuery` and `AccountsResult` bind identity and product, validate typed unique display
  entries and require an opaque membership version.
- `AccountMenuReader` uses only supplied internal composition seams. With a present version it may
  use the matching local entry; without it, it never asks for any surviving old list. It performs a
  fresh supplied transport read and overwrites the local tuple with TTL **300 seconds**.
- Any transport/protocol failure returns an unavailable empty menu. A successful empty result stays
  an available empty menu, so callers can distinguish an authority response from an outage.
- `authorizeClick()` always delegates to the supplied central-authorization seam. Menu display is
  not an access grant and cannot create a cached-menu-to-SSO fallback.

## Local acceptance

`AccountSwitcherTest` proves all target negative boundaries with deterministic disposable fixtures:

1. Loss of only the version key leaves a historic list present, but a restarted counter that
   repeats `7` is freshly recomputed and returns no revoked account; no historic-list lookup occurs.
2. Zero-active, regrant, and duplicate authoritative response keep exactly one current regranted
   entry.
3. A same-identity second product does not cross-hit the first product's cache tuple.
4. A failure or identity/product echo mismatch yields unavailable/empty output.
5. A stale-menu click invokes the authorizer once and preserves its denial.

schema needs exact `PUBLIC-API`/major and `SWITCHER-AUTHORITY` acceptance. P7.1 owns the central
fallback disagreement: recovering the same numeric version cannot prove that an old list is current.

state to restore.
