### P6.18 — FlexCRM backend/API и пакетная композиция

**Intent:** Реализовать backend-состав B-24/B-13 через Laravel Actions/API и owning пакеты в текущем flexcrm; frontend/design отдельно вне FLEX-2 по D49.
**Why:** Сначала стабилизировать domain/API/tenancy/storage/package composition; требования будущего frontend/design владелец задаст отдельно.
**Scope Included:** Backend/API принятого состава B-24/B-13, presets/module/edition composition, workflow/attributes/RBAC/social/calendar по готовности owning contracts, approved account storage и backend tests. Backend auth/profile/Tasks evidence P11/P12 сохраняется; frontend максимум запускаемая заглушка, авторизация и пустой dashboard.
**Scope Excluded:** Продуктовый frontend/UX/design, новые workspace/Tasks/CRM/другие доменные экраны и подключение продуктовых Nuxt layers; будущая UI/browser acceptance вне FLEX-2. Код внешних пакетов без core-first среза; commerce P6.19, Studio P6.20, attendance P6.21, MCP P6.22, спутники P6.23/P6.24; отраслевые бизнес-функции и полный shared-data runtime между solutions.
**Inputs:** B-24/B-13/B-23 · D37/ADR-002 · P6.17 evidence · P11/P12/P13 · готовые пакеты P6.9–P6.16.
**Files:** app/, frontend/, packages/flexcrm/, packages/frontend/, solutions/, API contracts, tests; findings/P6.18-product-composition.md.
**Required Reads:** decisions/D49-backend-first-frontend-out-of-scope.md · decisions/D38-implementation-order-and-schema-approval.md · schema/approval.md · phases/P11/P11.md · phases/P12/P12.md · decisions/D37-nuxt-solution-applications.md · phases/P9/P9.md · docs/03_Dev/ADR/ADR-002-nuxt-solution-applications.md · docs/03_Dev/Architecture_FlexCRM.md · docs/03_Dev/Vertical_Solutions (FlexCRM).md.
**Implementation Rules:** P6.17 и используемые domain contracts готовы. Отсутствующий пакет не заменять заглушкой своего движка; его домен не включать в состав до готовности. Нет if industry в ядре; нет foreign DB access; права через owning policies. Frontend не развивать сверх boot/auth/пустого dashboard; сохранение legacy/prototype UI не является visual approval или поручением их мигрировать сейчас.
**Code Guidance:** HTTP validation/authorization → DTO → Action. OpenAPI и типизированные backend DTO/contracts; existing frontend transport поддерживается только по необходимости boot/auth regression. Preset/module installer не является Docker provisioner. Будущий Task/report связывается контрактом и локальной транзакцией, но не реализуется в первом контуре. Общие auth/Tasks и пустые отрасли не закрывают весь состав P6.18 автоматически.
**Validation:** Backend scope checklist B-24 заполнен evidence · tenant/account A→B отрицательные API/integration тесты зелёные · edition gates проверены · OpenAPI/DTO contracts соответствуют runtime · выбранные модули работают через owning пакеты · isolation/install/dependency/release gates имеют отдельное evidence · отсутствующие домены не помечены готовыми. Frontend проверяется максимум по boot/auth/пустому dashboard и нужной регрессии основы; продуктовые UI/Nuxt E2E не требуются и не заявляются пройденными.
**Deliverables:** Проверенная backend/API композиция и фактический охват; evidence P6.18 с исключённым frontend/design scope; согласованные statuses/handoff. Это не готовность полного UI или production.
