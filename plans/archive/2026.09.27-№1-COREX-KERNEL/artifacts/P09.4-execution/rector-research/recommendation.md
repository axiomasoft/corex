# Rector Laravel dependency architecture research

Captured 2026-10-07, preparation unit P09.4/U4. This report recommends a solution; it does not enact a plan decision or change manifests/source. Full Perplexity responses and primary-source captures are adjacent to this file.

## Recommendation

Implement a bounded, repository-owned **development-only Laravel Rector rule subset**, using the supported native Rector 2 rule API. Import the exact three sets required by CoreX from official Rector-Laravel 2.6.2 commit `c0f9a2ff7365cec45d4dc64223608e7cec74604a`; retain their complete production dependency closure and original MIT attribution. Rename all local symbols into an honest own namespace such as `CoreX\\Tooling\\Rector\\Laravel`, remove the obsolete documentation methods/interface, and register the three local configs directly. Remove the upstream extension dependency and its now-unneeded external contracts package from the root lock. Keep strict Composer audit unchanged.

This is an explicitly maintained derivative with a deterministic importer, provenance and real regression fixtures, rather than a renamed package pretending to be the upstream release. It needs no `replace`/`provide`, no fabricated upstream package/version/source metadata, no abandonment exception, no extra installable tooling root and no external repository creation. Its ownership burden is limited to the rules CoreX actually runs. Keep the existing reviewed Rector 2.6.7 initially; evaluate 2.7 separately against its PHPStan 2.3 requirement and the full CoreX analysis suite.

## Verified facts

- Packagist's current newest stable Laravel extension is 2.6.2. It requires `rector/rector ^2.6.4`, `webmozart/assert ^1.11 || ^2.0` and `symplify/rule-doc-generator-contracts ^11.2`. The contracts package is abandoned without a suggested replacement; its latest release is 11.2.0. The documentation generator is also abandoned (latest 12.2.5), so moving the old contracts into another maintained development root does not resolve a strict audit of every installable root. [Extension metadata](https://repo.packagist.org/p2/driftingly/rector-laravel.json), [contracts metadata](https://repo.packagist.org/p2/symplify/rule-doc-generator-contracts.json), [generator metadata](https://repo.packagist.org/p2/symplify/rule-doc-generator.json).
- Current upstream main `1ce1c4a797bf3fb3f5852f87372bf6809a5c4868` still requires these contracts and its local `AbstractRector` implements their interface. The open issue #574 has one community comment and no linked fix branch/PR. The enumerated open PRs and upstream branches contain no proposed documentation-dependency migration. PR #277 historically retained the interface for generation of the rule overview. This is an unresolved upstream problem, not an announced roadmap. [Current manifest](https://github.com/driftingly/rector-laravel/blob/main/composer.json), [issue #574](https://github.com/driftingly/rector-laravel/issues/574), [PR #277](https://github.com/driftingly/rector-laravel/pull/277).
- Rector's official 2.0 upgrade path permits rules without `getRuleDefinition()`. Root Rector 2.6.7's runtime `RectorInterface` requires node types and transformation behavior, without the documentation interface. The extension has 128 documentation methods; read-only AST removal of their bodies and return types leaves only the abstract base class's obsolete interface reference. Thus the documentation layer can be removed without rewriting the transformation implementations. [Official Rector 2.0 announcement](https://getrector.com/blog/5-new-features-in-rector-20), [native runtime interface](https://github.com/rectorphp/rector/blob/2.6.7/src/Contract/Rector/RectorInterface.php).
- Rector 2.6.7 bundles these contracts **unprefixed** under `Symplify\\RuleDocGenerator`, as verified in its classmap and source scoping configuration. The dependency's availability inside that bundle does not establish a supported external replacement package or a stable API promise. A solution relying on that internal copy preserves the obsolete coupling. Perplexity/upstream-comment shorthand saying the contracts are scoped must not be interpreted as prefixed namespaces. [Bundled classmap](https://github.com/rectorphp/rector/blob/2.6.7/vendor/composer/autoload_classmap.php), [scope configuration](https://github.com/rectorphp/rector-src/blob/main/scoper.php).
- The latest Rector stable is 2.7.0 (2026-10-06), requiring PHPStan `^2.3.0`; an update does not remove the extension's separate contracts requirement. [Rector metadata](https://repo.packagist.org/p2/rector/rector.json).
- The available host Composer is 2.8.3. Official 2.8.12 source/schema supports only global abandonment treatment. The exact `audit.ignore-abandoned` feature was introduced in **2.9.0-RC1**, not 2.8. Current `policy.abandoned.ignore` documentation describes newer behavior and cannot be assumed to work in the installed CLI. An exact exception would require a toolchain update or a separate explicit debt protocol; neither makes an unqualified strict audit clean. [Official changelog](https://github.com/composer/composer/blob/main/CHANGELOG.md), [2.8.12 config](https://github.com/composer/composer/blob/2.8.12/src/Composer/Config.php), [2.8.12 schema](https://github.com/composer/composer/blob/2.8.12/res/composer-schema.json).

## Options compared

| Option | Assessment |
| --- | --- |
| Update Rector or use upstream Laravel main | No abandonment fix. Main adds unreleased behavior; Rector 2.7 also moves the analysis dependency target. |
| Another Laravel extension | No complete substitute found. The old `rector/rector-laravel` name is abandoned in favor of driftingly; `jcergolj/rector-for-laravel` delegates to driftingly. Custom generic/service-mocking packages cover isolated features, not all three required sets. |
| Exact expiring abandonment exception | A transparent temporary debt carrier could preserve vulnerability rejection and reject all other abandoned packages, but it changes the required strict audit contract and retains an obsolete external dependency. Not selected. |
| Global report/ignore, `--no-dev`, omit a tooling root | Violates the gate by losing findings or scope. Rejected. |
| Declare the bundle replaces the contracts | No supported upstream replacement API found; root pretending to provide a third-party package is not a sustainable dependency contract. Rejected. |
| Real maintained contracts fork | Defensible only with actual code ownership, tests, licensing and update process. The code is small (13 PHP files, 341 lines), but this retains a documentation system not needed for CoreX's transformations and introduces a new maintenance surface. Inferior to removing the dependency. |
| Whole Rector-Laravel fork | Can remove documentation coupling while retaining every rule, but CoreX would own an unrelated broad Laravel upgrade catalog. Excess scope for three local sets. |
| Bounded native root development subset | Preserves the required transformations, removes the obsolete coupling, keeps audit strict and limits ownership to a measured dependency closure. **Selected.** |

Alternative-package observations are backed by captured Packagist manifests and search results, not claims that no future or unlisted extension can exist.

## Exact implementation scope

The immutable 2.6.2 source has **25 Laravel quality rules, 4 collection rules and 7 type rules**, not 27 quality rules: 36 rule classes. The three sets and upstream default config add two node visitors; their AST dependency closure is **46 production class files**. There are no unresolved local class edges. `used-set-dependency-closure.json` records every class, source path, dependency, immutable URL, SHA-256 and official Git blob SHA. All 46 installed source files matched the official pinned Git tree byte for byte.

The ten non-rule classes consist of the local abstract base, two visitors, two analyzers, one factory, three value objects and the generic-relations abstract base. Preserve the default visitors (`ArrayDimFetchContextNodeVisitor`, `RandomEnumContextNodeVisitor`) and all existing Composer version constraints/attributes. For example, legacy/new/pivot relation generic formats select different Laravel version ranges. Do not widen them or select Laravel 13-only transforms in a shared Laravel 12 minimum target.

Suggested owned paths for a subsequent implementation unit:

- `scripts/quality/rector/Laravel/`: 46 derived source files, three local set configs plus the small shared visitor config, original MIT license and a README explaining ownership.
- A deterministic importer and committed provenance/selection manifest under the same tooling scope. Inputs are the immutable official commit/tree and selected class list. Verify each input hash; use AST changes restricted to local namespace references, documentation methods/interface and non-executable documentation imports. Produce deterministic formatting and output hashes. A regeneration check must fail on modified inputs, missing closure, unexpected transformations or any generated-byte drift.
- Official fixture/test support under the owning tooling test scope, with a hermetic root test harness. Root `autoload-dev` should expose the honest own namespace only to development; no consumer package may require or export these rules.
- Root `rector.php`, `composer.json` and `composer.lock` are integrator-owned changes: replace the three vendor set references with local configs, drop driftingly, retain Rector 2.6.7, and explicitly declare the already-used `webmozart/assert` dependency within an upstream-supported range. Composer must actually remove the external contracts package. No Composer metadata claiming the local subset is an upstream release.

Preserving a mirrored `src/config/tests` layout beneath the tooling base can keep fixture-relative config imports stable; another layout needs deterministic path adaptation in the importer. This is an implementation choice for the owning unit.

## Required proof before accepting the implementation

The pinned upstream tree maps the selected classes to **36 official test classes, 34 test directories, 261 unique test/support files and 173 unique fixture files**. The inventory includes shared generic-wrapper tests and fixture Composer version inputs; selecting directories merely from class names misses those cases. `official-used-rule-fixture-inventory.json` supplies exact official blob hashes. Representative official test/config/fixture source captures prove their use of `Rector\\Testing\\PHPUnit\\AbstractRectorTestCase` and the fixture-version override API.

Run the preserved official expected-output fixtures for every selected rule, including no-change fixtures and contextual `ArrayDimFetch` cases. Preserve rule-specific `provideComposerJsonFilePath()` overrides and their input JSON; otherwise root Laravel 13 can skip older version-bonded rules and create false confidence. Preserve required fixture `Source/` and stubs as hermetic test data, without registering upstream Laravel stubs globally over the real root framework. Upstream has 79 stub files, so the test-support closure must be established rather than inferred solely from production-class closure.

Validate selected-set membership and visitor registration, version bonding around the Laravel 12 lower target, importer byte regeneration, source syntax and root Rector dry run. Prove a modified generated rule or hash is rejected. Run strict root plus all-maintained-root Composer audit and require genuine exit 0 with no exception or omitted root; verify the external contracts package is absent from the resolved lock. Run root lint and affected PHPStan/Pest checks. PHP 8.4 and PHP 8.5 compatibility still requires execution evidence; source constraints alone are not test evidence.

No fixture or implementation acceptance test was run by this research unit. Its read-only checks establish feasibility and provenance, not behavioral GREEN.

## Maintenance and exit strategy

Own the derivative explicitly: review upstream releases/changes affecting the 36 selected rules, refresh the pinned input and official fixtures together through the importer, inspect the semantic delta, and rerun those gates. Keep the selection bounded instead of importing new upstream sets implicitly. Return to a clean upstream extension once a stable release removes the abandoned dependency, with fixture equivalence and full root validation before deleting the derivative. Root Composer audit still governs real dependencies; importer provenance and fixture regressions govern the owned source.

Raw evidence includes three Perplexity responses. The first advanced request failed with an extraction error; two narrower searches succeeded. Perplexity's recommendation aligns with a native rule API fork, but this bounded-subset recommendation also relies on independent official metadata and the measured source/fixture closure. No maintainer contact or external write occurred.
