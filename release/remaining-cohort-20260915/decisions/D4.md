## Decision

Для каждой детализации P1–P11 обязателен RAG через Perplexity до принятия итогового дизайна.
Ключевые архитектурные решения сопоставляются с минимум двумя независимыми первоисточниками;
сохраняются query, фактический successful tool response/digest, primary links, поддержанные claims,
альтернативы, выбор и влияние на другие фазы. Проверить ссылки непосредственно в первоисточниках.
Perplexity summary — retrieval/synthesis, не самостоятельное доказательство. Repository behavior
подтверждается actual source/tests/receipts; веб-результат его не подменяет. Не объявлять решение
«идеальным»: сравнить alternatives, failure modes и доказать соответствие ограничениям.

Политика full-plan-first: детализация всех P1–P11 → единая межфазовая архитектура/контракты/
зависимости/риски и design-finish → исполнение пунктов по DAG. До полного design-finish нельзя
начинать даже документальные execution items P1.1–P1.4. Routing моделей сохранён для будущего
исполнения; наличие detailed spec/bundle не означает admission. scripts/task-check.py --check design
выполняется до первой product mutation каждого item, включая P1.

Дизайн использует существующие source snapshots/R/AC/A/E каталоги, current code и declared future
producer contracts. Отсутствующий produced lock/release/AP — execution prerequisite, не разрешение
исполнить producer во время дизайна. Future inputs имеют exact path/schema/content obligations
и остаются dependency-not-ready до появления. Если исследование выявило неизвестный outcome,
решение снимается при дизайне; существенная последующая producer delta требует пересмотра
затронутого контракта/интегрированной картины, а не молчаливого предположения.

## Why / alternatives

- Generic Task protocol допускает per-item readiness и skeleton phases. Owner выбрал более строгий
  единый design boundary для этого плана; правила owner приоритетнее общих defaults.
- Дизайн→исполнение каждой фазы теперь запрещён: межфазовые сигнатуры/владение/inputs могут конфликтовать.
- Direct primary-source fallback остаётся полезным evidence, но не закрывает owner-required Perplexity step.
  Login/tool failure фиксируется; RAG не отмечается успешным по наличию ссылки или предыдущему summary.
- Perplexity вместо repository inspection и два совпадающих пересказа одного источника недопустимы.
